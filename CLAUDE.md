# Harlowe Parser — C# Library

## Project Overview
A C# library (netstandard2.0) for parsing and running Twine/Harlowe interactive fiction. Targets game engines (Unity, Godot, etc.) as the primary consumer — they implement `IRenderOutput` to drive whatever text layer they have (TextMeshPro tags, BBCode, plain text, etc.). Accepts Twine 2 HTML exports and Twee 3 source; emits Twee 3 back out.

> `ARCHITECTURE.md` is the structured deep-dive companion (integrator guide + contributor internals + glossary). `TODO.md` holds open bugs and the roadmap. `MACRO-DIVERGENCES.md` tracks per-macro gaps vs reference Harlowe.

## Build & Run
- **Framework:** Library targets `netstandard2.0` for maximum consumer reach (Unity 2018.1+, Godot 3/4, .NET Framework 4.6.1+, .NET 5+, Mono, Xamarin). Test project multi-targets `net48` + `net8.0`. Both SDK-style csprojs.
- **Build:** `dotnet build Twinelike.sln`
- **Test:** `dotnet test Twinelike.sln`
- **Output:** Library DLL (`harlowe_parser.dll`)
- The library csproj sits at the repo root and uses `<DefaultItemExcludes>` to keep it from globbing the test folder.

## Spec & reference sources
When a design question turns on how Twine/Twee/Harlowe is *supposed* to behave, fetch and quote the authoritative source before recommending a fix — don't reason from "what seems reasonable" or "what other tools probably do."

- **Twee 3 / serialization** → the Twee 3 spec at `github.com/iftechfoundation/twine-specs` (IFTF-maintained; closest to "official").
- **Harlowe macro/runtime semantics** → reference Harlowe source is checked into this repo at `references/harlowe-branch-default.zip` (snapshot of the canonical Mercurial repo at `foss.heptapod.net/games/harlowe`, branch `default`). Unzip to `/c/temp` or similar and read `ts/macrolib/*.ts` for macro semantics, `ts/internaltypes/*.ts` for runtime types. Heptapod sits behind Anubis bot-protection that blocks automated fetches — if `references/` is stale, ask the user to re-download via browser. Quote the relevant TypeScript, don't paraphrase.
- **Cross-tool compatibility claims** → check at least one popular impl (Tweego at `github.com/tmedwards/tweego`, Extwee at `github.com/videlais/extwee`) before claiming "tools generally do X."

Use `gh api -H "Accept: application/vnd.github.raw" repos/<owner>/<repo>/contents/<path>` to fetch raw files — WebFetch has session limits. Distinguish authority levels: the IFTF spec is closest to "official"; third-party compilers are popular but not authoritative.

**Don't write line numbers** into docstrings or comments when citing reference source — they rot when the reference repo updates. Cite by file path + a quoted identifier or short phrase the reader can grep for ("the `ws` pattern in `ts/markup/patterns.ts`", "`varref.ts`'s `set()` parent-walk loop").

When quoting reference regex character classes into C# XML doc comments, **do not paste literal Unicode characters** — U+2028 (LINE SEPARATOR) and U+2029 (PARAGRAPH SEPARATOR) are treated as line breaks by the C# lexer, which silently truncates the `///` block (CS1519). Spell the code points out as text (`U+2028`, `U+202F`, etc.).

Real example: the `\::` body-content escape in `TweeWriter` looked like a normal Twee feature worth fixing symmetrically — checking the spec + Tweego + Extwee revealed it's a library-local extension nobody else implements, flipping the recommendation from "fix the asymmetry" to "document and leave."

## Architecture
- **Entry points.** `new Harlowe(htmlText)` (Twine 2 HTML export) or `new TweeReader().Read(tweeText)` (Twee 3); both populate the same `Harlowe` story object. `new TweeWriter().Write(story)` emits Twee 3 (the only write format; HTML emit is out of scope).
- **Two parsing layers.** **Layer 1 (host)** has two front-ends: HtmlAgilityPack extracts `<tw-storydata>`/`<tw-passagedata>` and HTML-entity-decodes via `HtmlEntity.DeEntitize`; `TweeReader` splits Twee on `:: Name [tags] {position}` headers at column 0, special-cases `:: StoryTitle`/`:: StoryData` (hand-rolled `JsonReader`), and synthesizes sequential pids. **Layer 2 (Harlowe markup)** is shared: `HarloweTokenizer` → `HarloweBodyParser` (delegates to `HarloweExpressionParser` at every `MacroOpen`) → `PassageBody` AST on `HarlowePassage.Ast`. `HarlowePassage.Body`/`Branches` are derived from the AST by visitors. Both front-ends populate `HarlowePassage.RawBody` so `TweeWriter` emits clean passages verbatim (lazy reserialization — only `IsDirty` passages re-canonicalize via `MarkupPrinter`).
- **Two AST trees.** Node types split between **body** (prose, hooks, links, command macros — `IBodyNode`) and **expression** (macro arguments — `IExpressionNode`). The same `(name: ...)` syntax becomes `MacroNode` or `MacroCallNode` depending on position, which is why the split exists. Both trees use the visitor pattern.
- **Tokenizer** (`HarloweTokenizer`) covers every `TokenType` and operator from the manual's precedence table — multi-word operators (`is not`, `is in`, `is a`, `does not contain`, …) fused at lex time, the whitespace-sensitive `'s`, the digit-leading `2bind`, the `-type` TypedVar suffix. String literals are cooked at lex time (JS-spec escape set `\n \r \t \b \f \v \0 \\ \' \" \xHH \uHHHH` decoded into the token's `Value`; unknown escapes drop the backslash, matching reference Harlowe's JS evaluator). Uses a mode stack of `Frame { Mode, ParenDepth }` (Body vs Expression with per-frame paren depth so `)` is disambiguated as `ParenClose` vs `MacroClose`) and an `_inLink` flag that suppresses macro/hook markup inside `[[…]]`.
- **Parsers** live in `Parsing/`. Both share a `TokenCursor` so the body parser hands the cursor to the expression parser at every macro-arg list. `HarloweExpressionParser` is precedence-climbing (lower order = tighter binding); binary ops are left-associative, `and`/`or` share order 13. Branch links use `[[display text->passage name]]`; `DeEntitize` runs before tokenization so the tokenizer sees raw `->`.
- **Runtime** (`Runtime/`). `ExpressionEvaluator` (`IExpressionVisitor` → `HarloweValue`) and `BodyRenderer` (`IBodyVisitor` pushing through `IRenderOutput`) share a `MacroContext` (variable store, RNG, pending-goto flag, last-conditional flag, render-passage callback). `MacroRegistry` is a flat name→`IMacro` directory that also implements `IMacroInvoker` so the evaluator can dispatch nested `MacroCallNode`s. `to`/`into` assignment is handled by the evaluator (mutates via `IVariableStore`); `(set:)`/`(put:)` are near-no-op macros (work already done). `(if:)`/`(unless:)`/`(else:)` write `LastConditional`; the renderer reads it to decide hook rendering and resets it after any non-conditional macro so `(else:)` only pairs with the immediately preceding conditional. Errors propagate as `HarloweValue.Error` (every operator short-circuits) and exit through `IRenderOutput.Error`, never thrown.
- **Changer architecture** is descriptor-patch (matches reference). A `Changer` carries a flat list of `IChangerPatch`; each patch mutates a fresh `HookDescriptor` (Styles + Iteration + Revision + Interaction). The renderer executes the finished descriptor — interaction wrap + handler if `Interaction`, else splice if `Revision`, else loop if `Iteration`, else push/render/pop the styles. `(text-style:)`→`StylePatch`; `(for:)`→`IterationPatch`; `(replace:)`/`(append:)`/`(prepend:)`→`RevisionPatch`; click/hover→`InteractionPatch`. `Changer.Apply`'s `renderHook` is `Action<IRenderOutput>` — usually the live output, but a detached `RenderTreeBuilder` for revision/interaction so source can be spliced or stashed. `Changer.ApplyTo(IRenderContainer, Enchantment source = null)` is the dual entry used by `(change:)`/`(enchant:)`: wraps an *already-rendered* node's children in the changer's style layers; the optional source tag lets the enchant pass re-run idempotently.
- **Render tree** (`Runtime/Rendering/`) sits between `BodyRenderer` and `IRenderOutput` — an addressable, mutable representation of rendered content (the analogue of reference's `<tw-hook>` DOM). `BodyRenderer` renders into a `RenderTreeBuilder`, which *is* an `IRenderOutput` (so `Changer.Apply` retargets onto the tree for free) plus `BeginHook`/`EndHook` and `BeginInteractive`/`EndInteractive`. `RenderTreeFlusher` walks the finished tree and replays the identical event stream at the real output. `RenderHookNode` is the addressable unit (anonymous hooks get one with a null name); `RenderInteractiveNode` brackets a click/hover region; `HookResolver.Resolve` is the `selectHook` analogue (`?passage`/`?page`→root, `?link`→links, named→hooks); `TextOccurrenceFinder` wraps literal substring matches as addressable hooks for string-target revision. Revision macros mutate the tree; `RenderNode.Clone` keeps each target's splice independent.
- **Enchantments** are persistent restylings. `(enchant: ?target, changer)` registers an `Enchantment` on `MacroContext.Enchantments`; `StorySession` runs `EnchantmentPass.Update` over the finished tree after each render and dispatch (the `updateEnchantments()` analogue). The pass is **idempotent**: `Disenchant`s first (unwrapping every `RenderStyleNode` tagged with a `SourceEnchantment`) then re-applies, so any number of runs leaves a single correct application. `(change:)` is the one-shot sibling: `ApplyTo`s immediately against the tree built so far; its wraps carry no source tag and survive across passes.
- **Interactive channel + dispatch.** `IRenderOutput` brackets click/hover regions with `BeginInteractive(InteractiveRegion)`/`EndInteractive()` — symmetric with `PushStyle`/`PopStyle`. Each click/hover macro wraps its `?target` matches in a `RenderInteractiveNode` and registers a `ClickHandler` on `MacroContext.ClickHandlers` keyed by region id. Composed style layers become `RenderStyleNode`s around the interactive node, each tagged with the same region id via `SourceRegionId` so the dispatch unwrap removes them alongside the interactive wrap. The session keeps the live tree + handlers between renders; the host reports an event via `StorySession.DispatchEvent(regionId)`, which fires the handler — unwraps the consumed region, renders the deferred hook into a detached builder, splices a `Clone` into every re-resolved target via the revision machinery, re-runs the enchant pass, re-flushes. No whole-passage re-render. All matches of one call share one region id; handlers are single-use; a `(goto:)` in a deferred hook navigates after dispatch.
- **Lambda layer.** `LambdaNode` covers every lambda permutation (`where`/`via`/`making`/`each` + implicit-`it`) via nullable clause fields. `HarloweValueKind.Lambda` + `LambdaValue` wrap the AST as an opaque value (reference equality). `LambdaInvoker` is the shared utility every lambda-consuming macro routes through: binds the parameter + `it` slot + 1-indexed `pos` slot per item via `PushBinding`/`PushItBinding`/`PushPosBinding` (IDisposable scope-restore), evaluates the clause through a fresh `ExpressionEvaluator`, restores on dispose. Lambdas see the caller's store at invocation time — no closure capture.
- All source lives in `HarloweParser/`; data models are simple public-field classes.

## Key Files
- `Harlowe.cs` — main entry point: metadata extraction, passage indexing, AST wiring. Editing API: story-level fields (`StoryName`, `StartNode`, `Creator`, `CreatorVersion`, `Ifid`, `Format`, `FormatVersion`, `StoryDataExtras`) have setters; public parameterless ctor; `AddPassage` (auto-synthesizes pid), `RemovePassage`, `RenamePassage` (re-keys the lookup), `Passages` enumerator.
- `BodyVisitors.cs` — internal `BranchCollector` and `BodyTextRenderer` `IBodyVisitor`s used by both loaders to derive `HarlowePassage.Branches`/`Body` from the AST (static `Collect(ast)`/`Render(ast)` helpers). Centralized so a new body-AST node needs one `Visit` override per visitor.
- `HarlowePassage.cs` — passage model (Pid, Name, Body, Tags, Branches, Ast, RawBody, Position, IsDirty).
- `Branch.cs` — link model (Text, Name).
- `Twee/` — Twee 3 read + write. `TweeReader` (header parsing + body routing through the tokenizer/body parser), `JsonReader`/`JsonWriter` (hand-rolled minimal JSON for `:: StoryData`; avoids dragging Newtonsoft/System.Text.Json into consumers), `MarkupPrinter` (`IBodyVisitor`+`IExpressionVisitor` walking AST back to canonical markup; precedence-driven parens; smart-quoted strings), `TweeWriter` (story → Twee; lazy reserialization via `IsDirty`; overlays typed StoryData fields onto `StoryDataExtras` so unknown JSON keys round-trip; re-escapes body lines starting with `::`).
- `Tokens/` — `ITokenizer`, `Token`, `TokenType`, `HarloweTokenizer` (all operators, multi-word fusion, `'s`, `2bind`, `-type`).
- `Parsing/` — `TokenCursor`, `IExpressionParser`/`HarloweExpressionParser` (precedence-climbing), `IBodyParser`/`HarloweBodyParser` (recursive descent with hook attachment via whitespace-skipping lookahead).
- `Ast/Body/` — body AST nodes (`MacroNode`, `HookNode`, `LinkNode`, `TextNode`, `NewlineNode`, `VariableNode`, `HtmlNode`, `ChangerChainNode`, `ParseErrorNode`, `PassageBody`) with `IBodyVisitor`. `ChangerChainNode` carries an expression (`+`-chain of `MacroCallNode`s or a `VariableRefNode`) plus an optional hook — runtime applies as Changer if the result is one, else value-then-hook. `ParseErrorNode` is the in-prose error stub for unparseable source; carries the diagnostic + an `OriginalSource` field so `MarkupPrinter` can round-trip; `IsWhollyParseError(body)` detects the loader-stub shape (single child) vs partial recovery.
- `Ast/Expression/` — expression AST nodes (`LiteralNode`, `IdentifierNode`, `VariableRefNode`, `BinaryOpNode`, `UnaryOpNode`, `MacroCallNode`, `ArrayNode`, `DatamapNode`, `DatasetNode`, `LambdaNode`, `HookRefNode`) with `IExpressionVisitor`. `LambdaNode` carries nullable clause fields (Where/Via/When + Making accumulator + `IsEach`). `HookRefNode` is a `?name` reference carrying `Steps` (ordinal narrowing folded from chained `'s`).
- `Runtime/` — `HarloweValue`/`HarloweValueKind` (tagged union: `Error`/`Changer`/`Lambda`/`HookName` variants), `IVariableStore`/`HarloweVariableStore` (story namespace = flat dict, temp namespace = stack of dicts pushed per hook; `it`/`pos` slots; deep-copy snapshots; `PushBinding`/`PushItBinding`/`PushPosBinding`/`PushTempScope` IDisposable scope helpers), `ExpressionEvaluator`, `IEvaluationContext` (`time`/`visits`/`passage`/`turns`), `IMacroInvoker`, `IMacro`/`MacroContext`/`MacroRegistry`, `IRenderOutput`/`BufferedRenderOutput`/`HtmlRenderOutput`, `BodyRenderer`, `RenderResult`, `StyleSpec`, `InteractiveRegion`+`InteractionKind`, `LambdaValue`, `LambdaInvoker`, `HookDescriptor`+`IChangerPatch`/`StylePatch`/`IterationPatch`/`RevisionPatch`/`InteractionPatch`, `HookNameValue` (lazily-resolved `?name` query), `Enchantment`+`EnchantmentPass`, `ClickHandler`, `StorySession` (top-level engine surface, incl. `DispatchEvent`).
- `Runtime/Rendering/` — `RenderNode` (+ `Clone`) + concrete nodes (`RenderTextNode`/`RenderHtmlNode`/`RenderLinkNode`/`RenderErrorNode`/`RenderStyleNode` (carries `SourceEnchantment` + `SourceRegionId` tags)/`RenderHookNode`/`RenderInteractiveNode`/`RenderRoot`; containers implement `IRenderContainer`; `RenderNodes` clone helpers), `RenderTreeBuilder` (an `IRenderOutput` building the tree + `Begin/EndHook`, `Begin/EndInteractive`), `RenderTreeFlusher`, `HookResolver`, `TextOccurrenceFinder`.
- `Runtime/Macros/` — one class per file: `SetMacro`, `PutMacro`, `PrintMacro`, `IfMacro`, `ElseMacro`, `UnlessMacro`, `GotoMacro`, `DisplayMacro`, `RandomMacro`, `EitherMacro`, `AMacro`, `DmMacro`, `ModuloMacro`, `TextMacro`, `NumMacro`, `HistoryMacro`, `TextStyleMacro`, `FindMacro`, `AllPassMacro`, `AlteredMacro`, `SomePassMacro`, `NonePassMacro`, `ForMacro`, `FoldedMacro`, `RotatedToMacro`, `SortedMacro`, revision changers (`ReplaceMacro`/`AppendMacro`/`PrependMacro` sharing `RevisionChangers.Build`), enchantment commands (`ChangeMacro`/`EnchantMacro` sharing `EnchantmentMacroSupport.Validate`), and the click/hover family (`ClickMacro`/`ClickReplaceMacro`/`ClickAppendMacro`/`ClickPrependMacro` + `MouseOver*`/`MouseOut*` mirrors, grouped in `InteractionMacros.cs` over `InteractionChangers.Build`). `StandardMacros.RegisterAll(registry)` wires them up. `LambdaArgs.ExpandItems` auto-unpacks a single trailing array (deferred-`...`-spread workaround).
- `Runtime/Changer.cs` — descriptor-patch primitive. Internal `List<IChangerPatch>`; `Compose(other)` concatenates; `Apply(output, renderHook, ctx)` builds a fresh `HookDescriptor` then executes — splices via `RevisionSpec` if present (`RunRevision`), else loops via `IterationSpec`, else push/render/pops styles once. `FromStyle`/`FromIteration`/`FromRevision` factories; new changer kinds add patches without changing `Apply`. `Layers` preserved for diagnostics.
- `Runtime/StyleSpec.cs` — semantic styling description. Public-field class with named flags + value fields, structural equality, `IsEmpty`. Engine-agnostic — no HTML coupling.
- `Runtime/HtmlRenderOutput.cs` — adapter `IRenderOutput` that wraps an inner output and translates `PushStyle`/`PopStyle` to HTML. Bold/italic/underline/strike fold to short tags; any value field collapses to a single `<span style="…">`. `EscapeAttribute` HTML-escapes user values. Escaping contract (on `IRenderOutput`): `Text`, `Link`'s text arg, and `Error` are escaped; `Html` and `Link`'s target arg are forwarded raw. Ctor takes optional `interactiveHref` (default `javascript:void(0)`; empty omits the attribute) and rejects another `HtmlRenderOutput` as `inner` to catch the obvious double-escape footgun.
- `HarloweParser.Tests/` — tests for tokenizer, parsers, end-to-end HTML/Twee, runtime, changer pipeline, render tree, macros, and Twee read/write/markup-print round-trips.
- `TestFiles/testFile.html` — sample story (8 passages; some links target absent passages — useful for tolerant-parsing tests).

## Code Conventions
- **Namespace:** `Harlowe`
- **Indentation:** 2 spaces
- **Braces:** Allman style (opening brace on its own line)
- **Private fields:** `_camelCase` prefix
- **Public properties:** PascalCase; expression-bodied members where concise
- **Data models:** public fields (not properties) for simple DTOs (`HarlowePassage`, `Branch`)
- **Null handling:** return `null` or `string.Empty` for missing lookups, not exceptions
- **No LINQ** — explicit loops and Dictionary lookups

## Temp variable scoping
Temp variables (`_foo`) are hook-scoped via a stack of dictionaries inside `HarloweVariableStore`. Every `Visit(HookNode)` in `BodyRenderer` pushes a fresh scope; entry dies on hook exit. `Set` walks outer-to-inner and writes to the OUTERMOST existing declaration (matches reference's parent-walking `set()` loop in `ts/internaltypes/varref.ts`: "inner hooks can modify outer hooks' values"); fresh declarations land innermost. Story-scoped `$` vars share a single flat dictionary, unaffected. `(for:)` iterations get a fresh scope per iteration for free (each re-renders its hook through the same `Visit(HookNode)` path).

## Error Policy
In-prose errors, never exceptions — mirrors Harlowe's authoring model: a single bad expression renders an inline error at the spot it happened and the rest of the passage continues. `HarloweValue.Error` propagates through the evaluator (every operator short-circuits) and surfaces via `IRenderOutput.Error(message)`. No `try/catch` on the runtime hot path.

**Parse-error recovery.** Same contract at load time. Tokenizer/parser failures don't abort a load — loaders (HTML, Twee, `AddPassage`) catch `HarloweParseException` and substitute a synthetic `ParseErrorNode` via `Harlowe.MakeParseErrorAst`, so the rest of the story stays usable and the broken passage renders an in-prose error. The body parser additionally recovers *per node*: a `HarloweParseException` in `ParseNodes` is captured as a `ParseErrorNode`, then `TryAdvanceToResumePoint` advances to the next safe body-mode resync (newline or balanced macro-close) at the same hook depth so well-formed siblings still parse. `Harlowe.DecorateParseErrors` recursively prefixes nested ParseErrorNodes with the passage name; `Harlowe.EnsureWholeStubOriginalSource` stashes the source on a wholly-failed stub so `TweeWriter` can round-trip when `RawBody` is null. `TweeWriter.ResolveBody` distinguishes a wholly-stub AST (`IsWhollyParseError`) — prefers `RawBody` — from partial recovery (normal `IsDirty` path through `MarkupPrinter`).

## Status

**v3.1 + divergence-audit pass shipped, 1294 tests passing, no active slice.** Full per-version history is in `git log` (commit messages tagged by slice). The audit pass (against `references/harlowe-branch-default.zip`) closed nine concrete divergences (hook-scoped temp variables, `=` as `to`, `%` modulo, polymorphic `+`/`-`, lambda `pos` + `str` alias, `turn`/`turns` identifier, `incorrectOperator` hints, right-associative `of`) and filed the architectural-scale remainder in `TODO.md`.

The current shape rests on four load-bearing architectural pivots; everything else is built atop them and future slices should respect them rather than work around them.

- **Descriptor-patch changer model** (v2.3D, matches reference). A `Changer` is a flat `List<IChangerPatch>` over a `HookDescriptor`. New changer kinds drop in as new patch types + descriptor fields — `Apply` never grows a new top-level branch you can't isolate.
- **Render tree between `BodyRenderer` and `IRenderOutput`** (v3A). An addressable, mutable representation of rendered content, so revision/enchantment macros have something concrete to target. `RenderTreeBuilder` *is* an `IRenderOutput`, which is why `Changer.Apply` retargets onto the tree for free.
- **Semantic event channels on `IRenderOutput`** (v2.2 styles, v3D interactive). `PushStyle`/`PopStyle` and `BeginInteractive`/`EndInteractive` are the bracketing primitives engines map to native UI. The interface is the integration contract — grow it additively (parallel bracket pairs), don't reshape existing methods.
- **Hook-scoped variable stack** (divergence audit, matches reference `ts/internaltypes/varscope.ts`). Temp variables in a stack of dictionaries pushed at every `Visit(HookNode)`; `Set` walks outer-to-inner. Story vars stay a single flat namespace. `(for:)`, lambdas, and nested hooks all rely on this; future slices (especially save/load) must serialise the entire stack, not a flat dict.
