# Harlowe Parser — C# Library

## Project Overview
A C# library (netstandard2.0) for parsing and running Twine/Harlowe interactive fiction. Targets game engines (Unity, Godot, etc.) as the primary consumer — they implement `IRenderOutput` to drive whatever text layer they have (TextMeshPro tags, BBCode, plain text, etc.). Accepts Twine 2 HTML exports and Twee 3 source; emits Twee 3 back out.

> `ARCHITECTURE.md` is the structured deep-dive companion (integrator guide + contributor internals + glossary). `TODO.md` holds open bugs and the roadmap. `MACRO-DIVERGENCES.md` tracks per-macro gaps vs reference Harlowe.

## Build & Run
- **Framework:** Library targets `netstandard2.0` for maximum consumer reach (Unity 2018.1+, Godot 3/4, .NET Framework 4.6.1+, .NET 5+, Mono, Xamarin). Test project multi-targets `net48` + `net8.0`. Both SDK-style csprojs.
- **Build:** `dotnet build Twinelike.sln`
- **Test:** `dotnet test Twinelike.sln`
- **Output:** Library DLL (`twinelike.dll`) — `AssemblyName` is lower-case `twinelike` (avoids case-sensitive-filesystem breakage on Linux CI / IL2CPP). The NuGet `PackageId` stays PascalCase `Twinelike`; the in-code namespace stays `Harlowe.*`.
- The library csproj sits at the repo root and uses `<DefaultItemExcludes>` to keep it from globbing the test folder.

## Spec & reference sources
When a design question turns on how Twine/Twee/Harlowe is *supposed* to behave, fetch and quote the authoritative source before recommending a fix — don't reason from "what seems reasonable" or "what other tools probably do."

- **Twee 3 / serialization** → the Twee 3 spec at `github.com/iftechfoundation/twine-specs` (IFTF-maintained; closest to "official").
- **Harlowe macro/runtime semantics** → reference Harlowe source, branch `default`. The canonical Mercurial repo (`foss.heptapod.net/games/harlowe`) sits behind Anubis bot-protection that blocks automated fetches, so fetch from the `github.com/Codaea/harlowe-branch-default-2` mirror — a `branch/default` archive (currently `4.0.0-unstable` ≈ v3.3.8 + 67; its `.hg_archival.txt` records the exact node) carrying the same `ts/macrolib/*.ts` (macro semantics) and `ts/internaltypes/*.ts` (runtime types) — via the `gh api … /contents/<path>` raw pattern below. It's an unofficial personal mirror: verify provenance and treat it as less authoritative than the IFTF spec, and if it ever vanishes or goes stale, fall back to a local `references/harlowe-branch-default.zip` snapshot (gitignored — third-party Zlib source kept out of this MIT repo, so **not** committed; ask the user to download it via browser). The old `github.com/modality/harlowe` mirror is Harlowe 1.x — don't use it. Quote the relevant TypeScript, don't paraphrase.
- **Cross-tool compatibility claims** → check at least one popular impl (Tweego at `github.com/tmedwards/tweego`, Extwee at `github.com/videlais/extwee`) before claiming "tools generally do X."

Use `gh api -H "Accept: application/vnd.github.raw" repos/<owner>/<repo>/contents/<path>` to fetch raw files — WebFetch has session limits. Distinguish authority levels: the IFTF spec is closest to "official"; third-party compilers are popular but not authoritative.

**Don't write line numbers** into docstrings or comments when citing reference source — they rot when the reference repo updates. Cite by file path + a quoted identifier or short phrase the reader can grep for ("the `ws` pattern in `ts/markup/patterns.ts`", "`varref.ts`'s `set()` parent-walk loop").

When quoting reference regex character classes into C# XML doc comments, **do not paste literal Unicode characters** — U+2028 (LINE SEPARATOR) and U+2029 (PARAGRAPH SEPARATOR) are treated as line breaks by the C# lexer, which silently truncates the `///` block (CS1519). Spell the code points out as text (`U+2028`, `U+202F`, etc.).

Real example: the `\::` body-content escape in `TweeWriter` looked like a normal Twee feature worth fixing symmetrically — checking the spec + Tweego + Extwee revealed it's a library-local extension nobody else implements, flipping the recommendation from "fix the asymmetry" to "document and leave."

## Architecture
- **Entry points.** `new Harlowe(htmlText)` (Twine 2 HTML export) or `new TweeReader().Read(tweeText)` (Twee 3); both populate the same `Harlowe` story object. `new TweeWriter().Write(story)` emits Twee 3 (the only write format; HTML emit is out of scope).
- **Two parsing layers.** **Layer 1 (host)** has two front-ends: HtmlAgilityPack extracts `<tw-storydata>`/`<tw-passagedata>` and HTML-entity-decodes via `HtmlEntity.DeEntitize`; `TweeReader` splits Twee on `:: Name [tags] {position}` headers at column 0, special-cases `:: StoryTitle`/`:: StoryData` (hand-rolled `JsonReader`), and synthesizes sequential pids. **Layer 2 (Harlowe markup)** is shared: `HarloweTokenizer` → `HarloweBodyParser` (delegates to `HarloweExpressionParser` at every `MacroOpen`) → `PassageBody` AST on `HarlowePassage.Ast`. `HarlowePassage.Body`/`Branches` are derived from the AST by visitors. Both front-ends populate `HarlowePassage.RawBody` so `TweeWriter` emits clean passages verbatim (lazy reserialization — only `IsDirty` passages re-canonicalize via `MarkupPrinter`).
- **Two AST trees.** Node types split between **body** (prose, hooks, links, command macros — `IBodyNode`) and **expression** (macro arguments — `IExpressionNode`). The same `(name: ...)` syntax becomes `MacroNode` or `MacroCallNode` depending on position, which is why the split exists. Both trees use the visitor pattern.
- **Tokenizer** (`HarloweTokenizer`) covers every `TokenType` and operator from the manual's precedence table — multi-word operators (`is not`, `is in`, `is a`, `does not contain`, …) fused at lex time, the whitespace-sensitive `'s`, the digit-leading `2bind`, the `-type` TypedVar suffix, and the body-mode inline-format delimiters `''`/`//`/`~~`/`^^` (`FormatDelimiter`, doubled-only so lone single characters stay prose) and a `scheme://…` URL token (`TryScanUrl`/`MatchUrlLength`, mirroring reference's higher-priority `url` rule) consumed whole as text so its slashes never become italics, plus the comment tokens — `Comment` (`--`, both modes; outranks `-`/`-type` in expression mode per reference's rule order, suppressed inside links) and `HtmlComment` (a whole `<!-- … -->`, body mode only; unterminated stays prose). String literals are cooked at lex time (JS-spec escape set `\n \r \t \b \f \v \0 \\ \' \" \xHH \uHHHH` decoded into the token's `Value`; unknown escapes drop the backslash, matching reference Harlowe's JS evaluator). Uses a mode stack of `Frame { Mode, ParenDepth }` (Body vs Expression with per-frame paren depth so `)` is disambiguated as `ParenClose` vs `MacroClose`) and an `_inLink` flag that suppresses macro/hook markup inside `[[…]]`.
- **Parsers** live in `Parsing/`. Both share a `TokenCursor` so the body parser hands the cursor to the expression parser at every macro-arg list. `HarloweExpressionParser` is precedence-climbing (lower order = tighter binding); binary ops are left-associative, `and`/`or` share order 13. Branch links take all three separators (`[[text->target]]`, `[[text|target]]`, `[[target<-text]]`), with reference's multi-separator rule — rightmost `->`/`|` wins, else leftmost `<-`, unchosen separators stay literal text; a pure variable target (`[[Go->$next]]`) is resolved through the store at render time (reference evaluates markup in passage-name position). `DeEntitize` runs before tokenization so the tokenizer sees raw `->`.
- **Runtime** (`Runtime/`). `ExpressionEvaluator` (`IExpressionVisitor` → `HarloweValue`) and `BodyRenderer` (`IBodyVisitor` pushing through `IRenderOutput`) share a `MacroContext` (variable store, RNG, pending-goto flag, last-conditional flag, render-passage callback). `MacroRegistry` is a flat name→`IMacro` directory that also implements `IMacroInvoker` so the evaluator can dispatch nested `MacroCallNode`s. `to`/`into` assignment is handled by the evaluator (mutates via `IVariableStore`); `(set:)`/`(put:)` are near-no-op macros (work already done). `(if:)`/`(unless:)`/`(else-if:)`/`(else:)` return conditional *Changers* (reference model): a `ConditionalPatch` ANDs its decision into `HookDescriptor.Enabled`, so `(if: $cond) + (text-style: "bold")` composes and stores like any changer, and a disabled descriptor suppresses the whole application (styles/iteration/revision/interaction). `(else:)`/`(else-if:)` read `LastConditional` (reference's `lastHookShown`) at *call* time and bake the decision; the pairing is updated at hook-*application* time (`BodyRenderer.UpdateConditionalPairing`) — a shown attached hook sets it `true`, a hide sets it `false` only when the applying expression's *front macro name* is if/unless/else (an `(else-if:)` hide — or one from a stored changer in a variable or a composition fronted by a non-conditional — preserves the prior value, matching reference's name-gated `lastHookShown` write), attached booleans hide/show the hook and always write the pairing, and plain command macros/prose leave it alone — so an intervening `(set:)`/`(print:)` doesn't break an `(if:)`…`(else:)` pair, and a conditional nested in expression args can't corrupt it. An unattached changer in prose (bare `(if: $x)` or `$storedChanger`) is an in-prose error, as in reference. Each rendered hook is its own scope (`Visit(HookNode)` saves/clears/restores `LastConditional`), so a conditional nested inside a hook can't pair with an `(else:)` outside it. Errors propagate as `HarloweValue.Error` (every operator short-circuits) and exit through `IRenderOutput.Error`, never thrown.
- **Changer architecture** is descriptor-patch (matches reference). A `Changer` carries a flat list of `IChangerPatch`; each patch mutates a fresh `HookDescriptor` (Enabled + Styles + Iteration + Revision + Interaction; `ConditionalPatch` — the `(if:)` family — ANDs into Enabled, and a disabled descriptor applies nothing). The renderer executes the finished descriptor — record a persistent interaction if `Interaction` (the `InteractionPass` wraps + registers later), else splice if `Revisions` is non-empty (a list of `{target, mode}` pairs, reference's `newTargets` — revision patches append with a duplicate filter rather than overwrite, so composed revision changers accumulate), else loop if `Iteration`, else push/render/pop the styles. `(text-style:)`→`StylePatch`; `(for:)`→`IterationPatch`; `(replace:)`/`(append:)`/`(prepend:)`→`RevisionPatch`; click/hover→`InteractionPatch`. `Changer.Apply`'s `renderHook` is `Action<IRenderOutput>` — usually the live output, but a detached `RenderTreeBuilder` for revision/interaction so source can be spliced or stashed. `Changer.ApplyTo(IRenderContainer, Enchantment source = null)` is the dual entry used by `(change:)`/`(enchant:)`: wraps an *already-rendered* node's children in the changer's style layers; the optional source tag lets the enchant pass re-run idempotently.
- **Render tree** (`Runtime/Rendering/`) sits between `BodyRenderer` and `IRenderOutput` — an addressable, mutable representation of rendered content (the analogue of reference's `<tw-hook>` DOM). `BodyRenderer` renders into a `RenderTreeBuilder`, which *is* an `IRenderOutput` (so `Changer.Apply` retargets onto the tree for free) plus `BeginHook`/`EndHook` and `BeginInteractive`/`EndInteractive`. `RenderTreeFlusher` walks the finished tree and replays the identical event stream at the real output. `RenderHookNode` is the addressable unit (anonymous hooks get one with a null name); `RenderInteractiveNode` brackets a click/hover region; `RenderLinkNode` is a container (label = children, the `<tw-link>` analogue) — revision macros splice into it and string targets match inside it, while styling/arming wrap node-and-all *around* it (reference's `<tw-enchantment>`-around-`<tw-link>`); it flushes as the flat `Link` event while the label is plain prose (structural hook wraps included) and as a `BeginLink(target)`/`EndLink()` bracket when the label carries styles or armed regions. `HookResolver.Resolve` is the `selectHook` analogue (`?passage`/`?page`→root, `?link`→links, named→hooks); `TextOccurrenceFinder` wraps literal substring matches as addressable hooks for string-target revision/enchant/interaction — matching over the tree's *flattened* text so a match can bestride container boundaries (reference's `findTextInNodes`), with all fragments of one match moved into a single wrap at the first fragment's position (reference's `wrapAll` rehoming), so one match is always one hook node downstream. Revision macros mutate the tree; `RenderNode.Clone` keeps each target's splice independent.
- **Enchantments** are persistent restylings. `(enchant: target, changer)` takes a `?hookName` *or a string* (each occurrence wrapped as an addressable hook via `TextOccurrenceFinder` per pass) and a `Changer` *or a `via`-lambda* evaluated per non-empty match (1-based `pos`; a non-changer result replaces that match with the error and skips the rest — reference's `enchantScope`; completely empty hooks are skipped). The changer must be enchantable — `Changer.CanEnchant` errors on revision/interaction patches (reference's `notRevisionChanger`). Registers an `Enchantment` on `MacroContext.Enchantments`; `StorySession` runs `EnchantmentPass.Update` over the finished tree after each render and dispatch (the `updateEnchantments()` analogue). The pass is **idempotent**: `Disenchant`s first (unwrapping every `RenderStyleNode` — and string-occurrence `RenderHookNode` — tagged with a `SourceEnchantment`) then re-applies, so any number of runs leaves a single correct application; via-lambda evaluation restores `PendingGoto`/`PendingLoad`, so pass-time macro execution can't clobber a dispatch's queued navigation. `(change:)` is the one-shot sibling: applies immediately against the tree built so far through the shared `EnchantmentPass.Apply`; its wraps carry no source tag and survive across passes.
- **Interactive channel + dispatch.** `IRenderOutput` brackets click/hover regions with `BeginInteractive(InteractiveRegion)`/`EndInteractive()` — symmetric with `PushStyle`/`PopStyle`. Click/hover macros take a `?hookName` *or a string* target (each occurrence wrapped per pass via `TextOccurrenceFinder`, tagged `RenderHookNode.SourceRegionId`; empty string errors, reference's shared `[either(HookSet,String), optional(either(Changer, via-Lambda))]` signature) plus an optional second argument styling the *armed* region — a changer (same `notRevisionChanger` gate as `(enchant:)`) or a `via`-lambda evaluated per non-empty match with 1-based `pos` through the shared `EnchantmentPass.EvaluateViaLambda`. They are **persistent, mirroring enchantments**: each records an `Interaction` on `MacroContext.Interactions` (target query + arm changer/lambda + composed styles + deferred-hook renderer + combo mode + once flag + kind + stable region id) rather than wrapping inline; a plain (non-combo) macro also plants an anonymous *reveal anchor* node at the macro's own position. `InteractionPass.Update` runs after the main render *and* after every dispatch — `StripWraps` removes every interactive/region-tagged wrap, then each interaction is re-resolved against the complete tree, its non-empty matches (reference's `:empty` skip) wrapped in a `RenderInteractiveNode` (arm-changer style layers outside, tagged `SourceRegionId`), and the `ClickHandlers` registry rebuilt. Re-resolving every pass is why a forward-referenced `(click: ?b)` (target declared later) and click-chains across dispatch work. The session keeps the live tree + interactions + handlers between renders; the host reports an event via `StorySession.DispatchEvent(regionId)`, which drops the fired interaction (single-use — except `(click-rerun:)`, `once: false`, which stays armed), renders its deferred hook into a detached builder *wrapped in the composed styles* (so `(b)+(click:?a)[x]` reveals a bold `x` — styles land on content, not the armed region, as in reference), then either fills every reveal anchor (plain macros — the attached hook shows at the macro's position; anchors are found in the live tree by their `RenderHookNode.RevealRegionId` tag, which `Clone` copies, so an anchor spliced in as a clone from a revision-deferred render still reveals; rerun replaces the prior run's content) or splices a `Clone` into every target via the revision machinery (`-replace`/`-append`/`-prepend` combos; string-occurrence targets found by their `SourceRegionId` tag the same way), then re-runs the interaction + enchant passes and re-flushes. No whole-passage re-render; all matches of one call share one region id; a `(goto:)` in a deferred hook navigates after dispatch. The `-goto`/`-undo` *command* variants (`(click-goto:)`, `(click-undo:)`, hover mirrors — no attached hook, used bare in prose) register an `Interaction` directly via `InteractionCommandMacro` (goto: target passage existence-checked at call time; undo: in-prose error on the first turn via `MacroContext.CanUndo`); their dispatch navigates — `Goto(passage)` or `Undo()`+re-render — instead of filling anything (reference's `enchantDesc.goto`/`undo` branches). The `(link:)` family (`LinkMacro`: `link`/`link-replace`, `link-reveal`/`link-append`, `link-repeat`, `link-rerun`) *creates* its own armed label instead of targeting existing content — apply plants a `RenderHookNode.LabelRegionId`-tagged label hook (re-armed by tag each pass via `Interaction.LabelTarget`; also what `?link` matches) plus a reveal anchor, wrapping the label for the `-replace` variants (the fill removes the link) and a sibling otherwise (the link stays); `Interaction.RevealMode` picks the dispatch splice (reveal/repeat append, replace/rerun replace), and a consumed single-use label's tag is cleared so a spent link reverts to plain prose. The optional second changer styles the label; composed changers style only the revealed content, as in reference. `(link-goto:)` emits the same flat `Link` event the `[[...]]` syntax produces (reference: the link syntax is "a syntactic shorthand for (link-goto:)"); `(link-undo:)` plants a label-only interaction through the same undo dispatch branch, rendering its optional alt text instead when no past turn exists.
- **Lambda layer.** `LambdaNode` covers every lambda permutation (`where`/`via`/`making`/`each` + implicit-`it`) via nullable clause fields. `HarloweValueKind.Lambda` + `LambdaValue` wrap the AST as an opaque value (reference equality). `LambdaInvoker` is the shared utility every lambda-consuming macro routes through: binds the parameter + `it` slot + 1-indexed `pos` slot per item via `PushBinding`/`PushItBinding`/`PushPosBinding` (IDisposable scope-restore), evaluates the clause through a fresh `ExpressionEvaluator`, restores on dispose. Lambdas see the caller's store at invocation time — no closure capture.
- **Save / load** (`Runtime/Saving/`; design in `SAVE-LOAD-PLAN.md`). The session runs on a `Moment[]` timeline — completed turns `_past`, the live `_present`, undone `_future` (redo) — not an undo stack: `Goto` pushes present→past and clears future, `Undo`/`Redo` move the present between past/future. Each `Moment` holds its turn's forward `$`-var delta, auto-`(goto:)` redirect `Visits` trail, and sparse RNG `(Seed, SeedIter)`; `visits`/`(history:)`/`turns` are *derived* from the trails. Undo/redo/load restore the store + RNG to the restored turn's *start* and re-render to reproduce it (so relative `(set:)`s aren't double-applied; `MulberryRng` — reference's mulberry32 — makes `(random:)` reproduce). Serialisation is **source-based**, matching reference's `varscope.ts`: `HarloweValue.ToSource()` emits Harlowe source re-lexed + re-evaluated on load (`SaveSerializer`), and a `Changer` carries a `Source` stamped at the evaluator's macro-call/`+`-compose sites. `SaveSerializer.SerialiseTimeline` writes a `SaveBlobVersion`-wrapped JSON moment array (via `JsonWriter`; an empty turn compresses to a bare passage name); `DeserialiseTimeline` is atomic + validating (a vanished passage / corrupt value / newer version → error, nothing half-installed). `ISaveStorage` is the host backend (default `InMemorySaveStorage`; null disables saving), storing blob+filename per IFID-prefixed slot key (`SaveKeys`). `(save-game:)`→Bool, `(load-game:)`→a deferred navigation (stages `MacroContext.PendingLoad`; the session installs + shows the loaded passage after the body render; a re-load from a just-loaded passage errors — the session-held `_loadedGame` loop guard, cleared by any new-turn navigation), `(saved-games:)`→Datamap. **Boundary:** a save reproduces the present turn by re-render, so a dispatch-time (click/hover) `(set:)` made with no navigation isn't recaptured (documented on `StorySession.SaveGame`).
- All source lives in `HarloweParser/`; data models are simple public-field classes.

## Key Files
- `Harlowe.cs` — main entry point: metadata extraction, passage indexing, AST wiring. Editing API: story-level fields (`StoryName`, `StartNode`, `Creator`, `CreatorVersion`, `Ifid`, `Format`, `FormatVersion`, `StoryDataExtras`) have setters; public parameterless ctor; `AddPassage` (auto-synthesizes pid), `RemovePassage`, `RenamePassage` (re-keys the lookup), `Passages` enumerator, and the two **load-time diagnostics** — `GetBrokenLinks` (every navigation reference whose target passage is absent: the `[[…]]` syntax *and* literal targets of `(goto:)`/`(display:)`/`(link-goto:)`/the `(click-goto:)` family, via `ReferenceCollector` walking both the body and expression trees; computed targets skipped as undecidable) and `GetParseErrors` (every passage that didn't parse, via `ParseErrorCollector`; `IsWholePassage` separates a dead passage from one the body parser recovered inside). Both exist because nothing *forces* an authoring mistake to surface — inline errors only fire when a player reaches them and a broken passage doesn't abort a load, so a typo down an unplayed branch ships silently. Both are shaped for their real caller, a host engine showing the author what's wrong at load: passage + line + column + a printable `Message` per hit.
- `HarlowePassage.cs` — passage model (Pid, Name, Body, Tags, Branches, Ast, RawBody, Position, IsDirty).
- `Branch.cs` — link model (Text, Name).
- `BrokenLink.cs` / `ParseError.cs` — the two load-time diagnostics (`Harlowe.GetBrokenLinks` / `GetParseErrors`), same shape: passage + line + column + a printable `Message`. `BrokenLink` adds Target/LinkText/MacroName/`IsLink`; `ParseError` adds Detail/Source/`IsWholePassage` (a dead passage vs. one the parser recovered inside).
- `BodyVisitors.cs` — internal `IBodyVisitor`s: `BranchCollector` (derives `HarlowePassage.Branches`), `ReferenceCollector` (also an `IExpressionVisitor` — every passage reference, links and navigation-macro literals alike, for `GetBrokenLinks`), and `ParseErrorCollector` (every `ParseErrorNode`, hooks included, for `GetParseErrors`).
- `Twee/` — Twee 3 read + write. `TweeReader` (header parsing + body routing through the tokenizer/body parser), `JsonReader`/`JsonWriter` (hand-rolled minimal JSON for `:: StoryData`; avoids dragging Newtonsoft/System.Text.Json into consumers), `MarkupPrinter` (`IBodyVisitor`+`IExpressionVisitor` walking AST back to canonical markup; precedence-driven parens; smart-quoted strings), `TweeWriter` (story → Twee; lazy reserialization via `IsDirty`; overlays typed StoryData fields onto `StoryDataExtras` so unknown JSON keys round-trip; re-escapes body lines starting with `::`).
- `Tokens/` — `ITokenizer`, `Token`, `TokenType`, `HarloweTokenizer` (all operators, multi-word fusion, `'s`, `2bind`, `-type`).
- `Parsing/` — `TokenCursor`, `IExpressionParser`/`HarloweExpressionParser` (precedence-climbing), `IBodyParser`/`HarloweBodyParser` (recursive descent with hook attachment via whitespace-skipping lookahead).
- `Ast/Body/` — body AST nodes (`MacroNode`, `HookNode`, `FormatNode`, `LinkNode`, `TextNode`, `NewlineNode`, `VariableNode`, `HtmlNode`, `ChangerChainNode`, `ParseErrorNode`, `CommentNode`, `PassageBody`) with `IBodyVisitor`. `CommentNode` renders as nothing and carries `OriginalSource` (the `--` marker + eliminated construct, or a whole `<!-- … -->`) so `MarkupPrinter` round-trips author notes on dirty passages. `LinkNode`, `MacroNode`, and `ParseErrorNode` carry a 1-based `Line`/`Column` (0 = unknown, e.g. a hand-built AST) — the only nodes that do, because they're the ones the load-time diagnostics point at. Generally useful beyond that: the same positions would let a future slice put line numbers on in-prose runtime errors. `ParseErrorNode` also splits its baked render-time `Message` from a structured `Detail`, so tooling reads facts rather than regexing prose. `FormatNode` carries an `InlineFormat` (Bold/Italic) + children for `''bold''`/`//italic//`; the body parser folds matching `FormatDelimiter` pairs into it (mirroring reference's `foldChildren` — nearest match wins, crossed/unclosed delimiters degrade to literal text) and the renderer maps it to the same `StyleSpec` flag `(text-style:)` uses. `ChangerChainNode` carries an expression (`+`-chain of `MacroCallNode`s or a `VariableRefNode`) plus an optional hook — runtime applies as Changer if the result is one, else value-then-hook. `ParseErrorNode` is the in-prose error stub for unparseable source; carries the diagnostic + an `OriginalSource` field so `MarkupPrinter` can round-trip; `IsWhollyParseError(body)` detects the loader-stub shape (single child) vs partial recovery.
- `Ast/Expression/` — expression AST nodes (`LiteralNode`, `IdentifierNode`, `VariableRefNode`, `BinaryOpNode`, `UnaryOpNode`, `MacroCallNode`, `LambdaNode`, `HookRefNode`) with `IExpressionVisitor` (collection literals `(a:)`/`(dm:)`/`(ds:)` are `MacroCallNode`s, not dedicated nodes). `LambdaNode` carries nullable clause fields (Where/Via/When + Making accumulator + `IsEach`). `HookRefNode` is a `?name` reference carrying `Steps` (ordinal narrowing folded from chained `'s`).
- `Runtime/` — `HarloweValue`/`HarloweValueKind` (tagged union: `Error`/`Changer`/`Lambda`/`HookName`/`Colour` variants), `ColourValue` (immutable sRGB + alpha; built-in name table, hex parse, CSSWG HSL conversions, reference's additive `+` mix, `rgba()` CSS form — reference's `ts/datatypes/colour.ts`), `IVariableStore`/`HarloweVariableStore` (story namespace = flat dict, temp namespace = stack of dicts pushed per hook; `it`/`pos` slots; deep-copy snapshots; `PushBinding`/`PushItBinding`/`PushPosBinding`/`PushTempScope` IDisposable scope helpers), `ExpressionEvaluator`, `IEvaluationContext` (`time`/`visits`/`passage`/`turns`), `IMacroInvoker`, `IMacro`/`MacroContext`/`MacroRegistry`, `IRenderOutput`/`BufferedRenderOutput`/`HtmlRenderOutput`, `BodyRenderer`, `RenderResult`, `StyleSpec`, `InteractiveRegion`+`InteractionKind`, `LambdaValue`, `LambdaInvoker`, `HookDescriptor`+`IChangerPatch`/`StylePatch`/`IterationPatch`/`RevisionPatch`/`InteractionPatch`, `HookNameValue` (lazily-resolved `?name` query), `Enchantment`+`EnchantmentPass`, `Interaction`+`InteractionPass` (persistent click/hover pass, parallel to enchantments; `MacroContext.ClickHandlers` indexes armed interactions by region id), `StorySession` (top-level engine surface — render/navigate/undo/redo/`DispatchEvent` + `SaveGame`/`LoadGame`/`SavedGames`), `Moment` (one timeline turn: passage + `$`-var delta + redirect trail + sparse RNG state), `IRng`/`MulberryRng` (seedable mulberry32 PRNG). `HarloweValue.ToSource()` + `Changer.Source` are the value-level save primitives.
- `Runtime/Saving/` — the save model. `SaveSerializer` (value↔source and timeline↔blob), `DeserialiseResult` (atomic load outcome: `Past`/`Present`/`Error`), `SaveBlobVersion`, `ISaveStorage`/`InMemorySaveStorage` (host backend, blob+filename per key), `SaveKeys` (IFID slot-key namespacing), `SavedGameInfo`. ## Code Conventions
- **Namespace:** `Harlowe`
- **Indentation:** 2 spaces
- **Braces:** Allman style (opening brace on its own line)
- **Private fields:** `_camelCase` prefix
- **Public properties:** PascalCase; expression-bodied members where concise
- **Data models:** public fields (not properties) for simple DTOs (`HarlowePassage`, `Branch`)
- **Null handling:** return `null` or `string.Empty` for missing lookups, not exceptions
- **No LINQ** — explicit loops and Dictionary lookups

## Temp variable scoping
Temp variables (`_foo`) are hook-scoped via a stack of dictionaries inside `HarloweVariableStore`. Every `Visit(HookNode)` in `BodyRenderer` pushes a fresh scope; entry dies on hook exit. `Set` walks outer-to-inner and writes to the OUTERMOST existing declaration (matches reference's parent-walking `set()` loop in `ts/internaltypes/varref.ts`: "inner hooks can modify outer hooks' values"); fresh declarations land innermost. Story-scoped `$` vars share a single flat dictionary, unaffected. `(for:)` iterations get a fresh scope per iteration for free (each re-renders its hook through the same `Visit(HookNode)` path).

## Error Policy
In-prose errors, never exceptions — mirrors Harlowe's authoring model: a single bad expression renders an inline error at the spot it happened and the rest of the passage continues. `HarloweValue.Error` propagates through the evaluator (every operator short-circuits) and surfaces via `IRenderOutput.Error(message)`. No `try/catch` on the runtime hot path.

**Parse-error recovery.** Same contract at load time. Tokenizer/parser failures don't abort a load — loaders (HTML, Twee, `AddPassage`) catch `HarloweParseException` and substitute a synthetic `ParseErrorNode` via `Harlowe.MakeParseErrorAst`, so the rest of the story stays usable and the broken passage renders an in-prose error. The body parser additionally recovers *per node*: a `HarloweParseException` in `ParseNodes` is captured as a `ParseErrorNode`, then `TryAdvanceToResumePoint` advances to the next safe body-mode resync — a newline at the same hook depth, or exactly the macro-close parens the failed node still owes (`TokenCursor.NetMacroDepthSince` counts the net macro-opens its consumed span left unclosed) — so well-formed siblings, including a macro immediately after the broken construct, still parse. `Harlowe.DecorateParseErrors` recursively prefixes nested ParseErrorNodes with the passage name; `Harlowe.EnsureWholeStubOriginalSource` stashes the source on a wholly-failed stub so `TweeWriter` can round-trip when `RawBody` is null. `TweeWriter.ResolveBody` distinguishes a wholly-stub AST (`IsWhollyParseError`) — prefers `RawBody` — from partial recovery (normal `IsDirty` path through `MarkupPrinter`).

The current shape rests on five load-bearing architectural pivots; everything else is built atop them and future slices should respect them rather than work around them.

- **Descriptor-patch changer model** (v2.3D, matches reference). A `Changer` is a flat `List<IChangerPatch>` over a `HookDescriptor`. New changer kinds drop in as new patch types + descriptor fields — `Apply` never grows a new top-level branch you can't isolate.
- **Render tree between `BodyRenderer` and `IRenderOutput`** (v3A). An addressable, mutable representation of rendered content, so revision/enchantment macros have something concrete to target. `RenderTreeBuilder` *is* an `IRenderOutput`, which is why `Changer.Apply` retargets onto the tree for free.
- **Semantic event channels on `IRenderOutput`** (v2.2 styles, v3D interactive, `?link`-slice links). `PushStyle`/`PopStyle`, `BeginInteractive`/`EndInteractive`, and `BeginLink`/`EndLink` (structured link labels only — plain labels keep the flat `Link` event) are the bracketing primitives engines map to native UI. The interface is the integration contract — grow it additively (parallel bracket pairs), don't reshape existing methods.
- **Hook-scoped variable stack** (divergence audit, matches reference `ts/internaltypes/varscope.ts`). Temp variables in a stack of dictionaries pushed at every `Visit(HookNode)`; `Set` walks outer-to-inner. Story vars stay a single flat namespace. `(for:)`, lambdas, and nested hooks all rely on this. Save/load serialises only the flat story `$`-namespace (the per-turn delta) — temp vars are transient, rebuilt by the load's re-render, not persisted.
- **`Moment[]` session timeline** (save/load slice, matches reference `ts/state/moment.ts`). `_past`/`_present`/`_future` on `StorySession` replace the undo stack; each turn is a forward `$`-var delta + redirect `Visits` trail + sparse RNG `(Seed, SeedIter)`, with `visits`/`(history:)`/`turns` *derived* from the trails rather than stored. Undo, redo, and load all restore the store + RNG to a turn's *start* and re-render to reproduce it; save/load serialises this timeline source-based. Future work (a full-snapshot fidelity model, `(seed:)`, `(forget-undos:)`, a separate new-turn `(go-to:)` vs intra-turn `(redirect:)`) builds on it.
