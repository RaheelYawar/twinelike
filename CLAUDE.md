# Harlowe Parser — C# Library

## Project Overview
A C# library (netstandard2.0) for parsing and running Twine/Harlowe interactive fiction. Targets game engines (Unity, Godot, etc.) as the primary consumer — they implement `IRenderOutput` to drive whatever text layer they have (TextMeshPro tags, BBCode, plain text, etc.). Accepts Twine 2 HTML exports and Twee 3 source; emits Twee 3 back out.

> `ARCHITECTURE.md` is the structured deep-dive companion (integrator guide + contributor internals + glossary). `TODO.md` holds open bugs and the roadmap. `MACRO-DIVERGENCES.md` tracks per-macro gaps vs reference Harlowe. `COMPATIBILITY.md` records deliberate Harlowe-version differences (the future compatibility-profile switch table).

## Build & Run
- **Framework:** Library targets `netstandard2.0` for maximum consumer reach (Unity 2018.1+, Godot 3/4, .NET Framework 4.6.1+, .NET 5+, Mono, Xamarin). Test project multi-targets `net48` + `net8.0`. Both SDK-style csprojs.
- **Build:** `dotnet build Twinelike.sln`
- **Test:** `dotnet test Twinelike.sln`
- **Output:** Library DLL (`twinelike.dll`) — `AssemblyName` is lower-case `twinelike` (avoids case-sensitive-filesystem breakage on Linux CI / IL2CPP). The NuGet `PackageId` stays PascalCase `Twinelike`; the in-code namespace stays `Harlowe.*`.
- The library csproj sits at the repo root and uses `<DefaultItemExcludes>` to keep it from globbing the test folder.

## Spec & reference sources
When a design question turns on how Twine/Twee/Harlowe is *supposed* to behave, fetch and quote the authoritative source before recommending a fix — don't reason from "what seems reasonable" or "what other tools probably do."

- **Twee 3 / serialization** → the Twee 3 spec at `github.com/iftechfoundation/twine-specs` (IFTF-maintained; closest to "official").
- **Harlowe macro/runtime semantics** → reference Harlowe source, branch `default`. The canonical Mercurial repo (`foss.heptapod.net/games/harlowe`) sits behind Anubis bot-protection that blocks automated fetches, so fetch from the `github.com/Codaea/harlowe-branch-default-2` mirror — a `branch/default` archive (the pinned audit baseline is `4.0.0-unstable` = v3.3.8 + 67, Mercurial node `facd4762815b17e1de9cb2e2a6c47cd223d23858`, recorded in the snapshot's `.hg_archival.txt`; re-pin here when deliberately moving to a newer node — note `latesttag` reads v3.3.8 because the *last 3.x release*, v3.3.9, was tagged off a separate release branch, and its single fix is already in this node) carrying the same `ts/macrolib/*.ts` (macro semantics) and `ts/internaltypes/*.ts` (runtime types) — via the `gh api … /contents/<path>` raw pattern below. It's an unofficial personal mirror: verify provenance and treat it as less authoritative than the IFTF spec, and if it ever vanishes or goes stale, fall back to a local `references/harlowe-branch-default.zip` snapshot (gitignored — third-party Zlib source kept out of this MIT repo, so **not** committed; ask the user to download it via browser). The old `github.com/modality/harlowe` mirror is Harlowe 1.x — don't use it. Quote the relevant TypeScript, don't paraphrase.
- **Cross-tool compatibility claims** → check at least one popular impl (Tweego at `github.com/tmedwards/tweego`, Extwee at `github.com/videlais/extwee`) before claiming "tools generally do X."

Use `gh api -H "Accept: application/vnd.github.raw" repos/<owner>/<repo>/contents/<path>` to fetch raw files — WebFetch has session limits. Distinguish authority levels: the IFTF spec is closest to "official"; third-party compilers are popular but not authoritative.

**Don't write line numbers** into docstrings or comments when citing reference source — they rot when the reference repo updates. Cite by file path + a quoted identifier or short phrase the reader can grep for ("the `ws` pattern in `ts/markup/patterns.ts`", "`varref.ts`'s `set()` parent-walk loop").

When quoting reference regex character classes into C# XML doc comments, **do not paste literal Unicode characters** — U+2028 (LINE SEPARATOR) and U+2029 (PARAGRAPH SEPARATOR) are treated as line breaks by the C# lexer, which silently truncates the `///` block (CS1519). Spell the code points out as text (`U+2028`, `U+202F`, etc.).

Real example: the `\::` body-content escape in `TweeWriter` looked like a normal Twee feature worth fixing symmetrically — checking the spec + Tweego + Extwee revealed it's a library-local extension nobody else implements, flipping the recommendation from "fix the asymmetry" to "document and leave."

## Version policy
**Target: the newest Harlowe release, currently 3.3.9** (what Twine 2.12.1 ships; 4.0 is unreleased) **audited against the 4.0-unstable tip** (the pinned node above). Where 4.0 deliberately changed the language and the change is coherent, each major keeps its own behaviour through a compatibility switch: `--` comments and erroring unset variables belong to 4.0, so a 3.x story gets literal `--` and unset story variables reading as `0`. Where the manual and the released build disagree, follow the build, because that's what stories were tested against: `(move: $p into $q)` deletes `$p` in real 3.3.9 and 4.0-unstable, against its own article. Where the unstable branch is broken, follow 3.3.9 and say so in the code.

**The long-term promise is per-major lock-in: a story keeps the semantics of the major it declares, indefinitely.** Twine itself binds a story to the newest version within its major, so lock-in is per *major*, not per minor (a 3.2 story has been running under 3.3.9 rules in Twine for years), and the promise starts at 3.x — 1.x/2.x were never audited here. Delivery is one engine with append-only **compatibility profiles**, and the machinery ships (2026-07-20): `HarloweProfile` carries one get-only `bool` per switch, with `V3`/`V4`/`Latest` instances and a `Resolve(formatVersion)` reading the leading major. `HarloweStory.Profile` computes from `FormatVersion` per call (never cached, so it can't desync) and is host-overridable — but **the override must be passed to the loader** (`new HarloweStory(html, profile)`, `new TweeReader(profile)`), because lexical switches are decided before any post-load property can be assigned. Absent, unparseable and below-3 versions select V3, because guessing V4 would delete the prose after every `--`; only a major newer than we implement selects newest. `GetCompatibilityNotices()` is the third load-time diagnostic beside `GetBrokenLinks`/`GetParseErrors`, reporting each non-nominal case. Saves are pinned to `HarloweProfile.SaveFormat` and never follow the story — blob source is engine-emitted, so an author's `format-version` bump must not re-interpret existing saves.

**Whenever a decision turns on a version difference, record it** (macro docstring + `MACRO-DIVERGENCES.md`), because those tags are the profile's switch inventory. Two standing rules keep the switch count bounded: our *own* bugs are fixed under every profile (only differences reference intended between majors get a switch), and new-in-N macros stay registered under older profiles (under real 3.x an unknown macro was an in-prose error, so no shipped story depends on its absence). The inventory lives in `COMPATIBILITY.md` (append-only — add a row the moment a version difference is found, so a missing decision is visible as an absent row rather than an unwritten one) and the procedure in `COMPATIBILITY-PLAN.md`; rows 1 (`--` comment markup) and 2 (unset reads) are implemented, twelve rows remain inventory. Adding a switch requires adding a probe to `CompatibilityProfileTests`, which reflects over the switch properties and fails on any switch that doesn't change behaviour — the class of bug here produces silent drift, never a red test, so that harness is the real safeguard. A probe asserting *rendered output* is necessary but not sufficient: measured on row 1, undoing the `ScanText` guard alone fragments the token stream while rendering byte-identically, and only a token-level assertion catches it.

## Architecture
- **Entry points.** `new HarloweStory(htmlText)` (Twine 2 HTML export) or `new TweeReader().Read(tweeText)` (Twee 3); both populate the same `HarloweStory` story object. `new TweeWriter().Write(story)` emits Twee 3 (the only write format; HTML emit is out of scope).
- **Two parsing layers.** **Layer 1 (host)** has two front-ends: HtmlAgilityPack extracts `<tw-storydata>`/`<tw-passagedata>` and HTML-entity-decodes via `HtmlEntity.DeEntitize`; `TweeReader` splits Twee on `:: Name [tags] {position}` headers at column 0, special-cases `:: StoryTitle`/`:: StoryData` (hand-rolled `JsonReader`), and synthesizes sequential pids. **Layer 2 (Harlowe markup)** is shared: `HarloweTokenizer` → `HarloweBodyParser` (delegates to `HarloweExpressionParser` at every `MacroOpen`) → `PassageBody` AST on `HarlowePassage.Ast`. `HarlowePassage.Body`/`Branches` are derived from the AST by visitors. Both front-ends populate `HarlowePassage.RawBody` so `TweeWriter` emits clean passages verbatim (lazy reserialization — only `IsDirty` passages re-canonicalize via `MarkupPrinter`).
- **Two AST trees.** Node types split between **body** (prose, hooks, links, command macros — `IBodyNode`) and **expression** (macro arguments — `IExpressionNode`). The same `(name: ...)` syntax becomes `MacroNode` or `MacroCallNode` depending on position, which is why the split exists. Both trees use the visitor pattern.
- **Tokenizer** (`HarloweTokenizer`) covers every `TokenType` and operator from the manual's precedence table — multi-word operators (`is not`, `is in`, `is a`/`is an`, `does not contain`, …) fused at lex time, the whitespace-sensitive `'s`, the digit-leading `2bind`, the `-type` TypedVar suffix, the datatype-name literals (`num`, `string`, `even`, … — case-insensitive, ahead of the colour rule as in reference, and outranked by property-name position so `$dm's num` still reads a key), and the body-mode inline-format delimiters `''`/`//`/`~~`/`^^` (`FormatDelimiter`, doubled-only so lone single characters stay prose) plus `*`/`**`, whole `` `verbatim` `` spans, `---` rules, list markers (`* `, `0. `, `**`, `0.0.`) where a block may start (`ListMarker`), and a `scheme://…` URL token (`TryScanUrl`/`MatchUrlLength`, mirroring reference's higher-priority `url` rule) consumed whole as text so its slashes never become italics, plus the comment tokens — `Comment` (`--`, both modes; outranks `-`/`-type` in expression mode per reference's rule order, suppressed inside links) and `HtmlComment` (a whole `<!-- … -->`, body mode only; unterminated stays prose). String literals are cooked at lex time (JS-spec escape set `\n \r \t \b \f \v \0 \\ \' \" \xHH \uHHHH` decoded into the token's `Value`; unknown escapes drop the backslash, matching reference Harlowe's JS evaluator). Uses a mode stack of `Frame { Mode, ParenDepth }` (Body vs Expression with per-frame paren depth so `)` is disambiguated as `ParenClose` vs `MacroClose`) and an `_inLink` flag that suppresses macro/hook markup inside `[[…]]`. `MarkupFronts` is reference's `frontTokenStack`: it pairs hooks, `{…}`, inline formats and verbatim across the passage and records each pair in `Token.Partner`, so a token with no partner is literal text and surviving pairs always nest.
- **Parsers** live in `Parsing/`. Both share a `TokenCursor` so the body parser hands the cursor to the expression parser at every macro-arg list. `HarloweExpressionParser` is precedence-climbing (lower order = tighter binding); binary ops are left-associative, `and`/`or` share order 13. Branch links take all three separators (`[[text->target]]`, `[[text|target]]`, `[[target<-text]]`), with reference's multi-separator rule — rightmost `->`/`|` wins, else leftmost `<-`, unchosen separators stay literal text; a pure variable target (`[[Go->$next]]`) is resolved through the store at render time (reference evaluates markup in passage-name position). `DeEntitize` runs before tokenization so the tokenizer sees raw `->`.
- **Runtime** (`Runtime/`). `ExpressionEvaluator` (`IExpressionVisitor` → `HarloweValue`) and `BodyRenderer` (`IBodyVisitor` pushing through `IRenderOutput`) share a `MacroContext` (variable store, RNG, pending-goto flag, last-conditional flag, render-passage callback). `MacroRegistry` is a flat name→`IMacro` directory that also implements `IMacroInvoker` so the evaluator can dispatch nested `MacroCallNode`s. `to`/`into` assignment is handled by the evaluator (mutates via `IVariableStore`), including property-chain targets — `(set: $person's name to "Bob")`, `'s`/`of` chains, computed accessors evaluated once: the target path is resolved and canSet-validated *before* the RHS runs (error = zero mutation), `it` binds to the slot's current value, and the write rebuilds the chain **copy-on-write** (per-level shallow clone, reference varref.ts's `#mutateRight`; siblings stay shared) then re-`Set`s the root so the dirty-set save/undo delta sees it, with `SetIt` leaving `it` as the assigned value; the `random` data name resolves to a concrete position through the evaluator's session-shared `IRng` at path-resolve time (reference compiles it in `compilePropertyIndex`, which is also why assigning through it is legal), erroring on empty sequentials with reference's wording; `(set:)`/`(put:)`/`(move:)` are near-no-op macros — the work happens during arg evaluation, where `ValidateAssignmentOperators` (reference's typeChecker pre-pass, run at both macro-invocation sites) checks every argument's operator *before* any evaluates — a wrong operator (`(set: … into …)`, `(move: … to …)`) or a non-assignment argument errors with reference's "Please say…" wordings and nothing assigns — and `EvaluateMacroArgument` routes a `(move:)` `into`-arg through copy-then-delete: source read and delete share one frozen path resolve (computed accessors run once), the destination is assigned first (reference's order), then the source is deleted: a slot via `ApplyDelete` (array position spliced out, datamap key removed, string code point excised) with containers re-fetched post-assignment so overlapping source/dest work, or a whole variable via `IVariableStore.Delete`, recorded as a null in the turn's delta. A deletion that can't happen, like `length` or a colour data name, is skipped silently because reference ignores what `src.delete()` returns. `(unpack:)` destructures on the same choke point: its `into`-destination is a literal `(a:)`/`(dm:)` pattern walked as AST (`Destructure` — reference's `destructure()` over VarRef-bearing values, minus the unimplemented typed-var/rest/`(p:)` positions, which error pointedly), where variables and property chains bind, every other position must `matches` the source (so a bare datatype there is a check that binds nothing), nested patterns recurse, and bindings execute *reversed* (as in reference — which is what lets `(move:)` take the same pattern destinations and delete each bound source slot descending, no index shift); the pre-pass also carries reference's XOR dest-shape gate — `(set:)`/`(put:)` reject a pattern destination, `(unpack:)` requires one. `(if:)`/`(unless:)`/`(else-if:)`/`(else:)` return conditional *Changers* (reference model): a `ConditionalPatch` ANDs its decision into `HookDescriptor.Enabled`, so `(if: $cond) + (text-style: "bold")` composes and stores like any changer, and a disabled descriptor suppresses the whole application (styles/iteration/revision/interaction). `(else:)`/`(else-if:)` read `LastConditional` (reference's `lastHookShown`) at *call* time and bake the decision; the pairing is updated at hook-*application* time (`BodyRenderer.UpdateConditionalPairing`) — a shown attached hook sets it `true`, a hide sets it `false` only when the applying expression's *front macro name* is if/unless/else (an `(else-if:)` hide — or one from a stored changer in a variable or a composition fronted by a non-conditional — preserves the prior value, matching reference's name-gated `lastHookShown` write), attached booleans hide/show the hook and always write the pairing, and plain command macros/prose leave it alone — so an intervening `(set:)`/`(print:)` doesn't break an `(if:)`…`(else:)` pair, and a conditional nested in expression args can't corrupt it. An unattached changer in prose (bare `(if: $x)` or `$storedChanger`) is an in-prose error, as in reference. Each rendered hook is its own scope (`Visit(HookNode)` saves/clears/restores `LastConditional`), so a conditional nested inside a hook can't pair with an `(else:)` outside it. The datatype comparisons are reference's pair in `ts/utils/operationutils.ts`: `is a`/`is not a` demand a `DatatypeValue` on the right and error otherwise, while `matches`/`does not match` are structural equality in which a datatype on *either* side is satisfied by the other side being of that type — which is what makes a collection with datatypes in it a pattern, and is the same walk `(unpack:)` uses per pattern position. Errors propagate as `HarloweValue.Error` (every operator short-circuits) and exit through `IRenderOutput.Error`, never thrown.
- **Changer architecture** is descriptor-patch (matches reference). A `Changer` carries a flat list of `IChangerPatch`; each patch mutates a fresh `HookDescriptor` (Enabled + Styles + Iteration + Revision + Interaction; `ConditionalPatch` — the `(if:)` family — ANDs into Enabled, and a disabled descriptor applies nothing). The renderer executes the finished descriptor — record a persistent interaction if `Interaction` (the `InteractionPass` wraps + registers later), else loop if `Iteration` (running any revision once per pass), else render into the targets if `Revisions` is non-empty (a list of `{target, mode}` pairs, reference's `newTargets` — revision patches append with a duplicate filter rather than overwrite, so composed revision changers accumulate), else push/render/pop the styles. `(text-style:)`→`StylePatch`; `(for:)`→`IterationPatch`; `(replace:)`/`(append:)`/`(prepend:)`→`RevisionPatch`; click/hover→`InteractionPatch`. `Changer.Apply`'s `renderHook` is `Action<IRenderOutput>` — usually the live output, a placeholder's builder for each revision target, or stashed for an interaction. `Changer.ApplyTo(IRenderContainer, Enchantment source = null)` is the dual entry used by `(change:)`/`(enchant:)`: wraps an *already-rendered* node's children in the changer's style layers; the optional source tag lets the enchant pass re-run idempotently.
- **Render tree** (`Runtime/Rendering/`) sits between `BodyRenderer` and `IRenderOutput` — an addressable, mutable representation of rendered content (the analogue of reference's `<tw-hook>` DOM). `BodyRenderer` renders into a `RenderTreeBuilder`, which *is* an `IRenderOutput` (so `Changer.Apply` retargets onto the tree for free) plus `BeginHook`/`EndHook` and `BeginInteractive`/`EndInteractive`. `RenderTreeFlusher` walks the finished tree and replays the identical event stream at the real output. `RenderHookNode` is the addressable unit (anonymous hooks get one with a null name); `RenderInteractiveNode` brackets a click/hover region; `RenderLinkNode` is a container (label = children, the `<tw-link>` analogue) — revision macros render into it and string targets match inside it, while styling/arming wrap node-and-all *around* it (reference's `<tw-enchantment>`-around-`<tw-link>`); it flushes as the flat `Link` event while the label is plain prose (structural hook wraps included) and, to an `ILinkLabelOutput`, as a `BeginLink(target)`/`EndLink()` bracket when the label carries styles, armed regions, HTML or errors (other outputs get it flattened to one `Link`). `HookResolver.Resolve` is the `selectHook` analogue (`?passage`/`?page`→root, `?link`→links, named→hooks); `TextOccurrenceFinder` wraps literal substring matches as addressable hooks for string-target revision/enchant/interaction — matching over the tree's *flattened* text so a match can bestride container boundaries (reference's `findTextInNodes`), with all fragments of one match moved into a single wrap at the first fragment's position (reference's `wrapAll` rehoming), so one match is always one hook node downstream. Revisions render in place (`Changer.RenderInPlace`, reference's `ChangeDescriptor.render`): every target is resolved first, each gets an empty placeholder, and each placeholder its own rendering, so a revision in the content lands on top and side effects run once per target. A target still being written has what's written moved aside first (`RenderTreeBuilder.MoveAside`); while the passage renders a revision only reaches what's before it, after ordinals pick (`HookResolver.ResolveBefore`); and a changer written directly in a placeholder a revision has emptied does nothing (`WritesIntoCutContent`), as reference's orphaned expression can't find its hook.
- **Enchantments** are persistent restylings. `(enchant: target, changer)` takes a `?hookName` *or a string* (each occurrence wrapped as an addressable hook via `TextOccurrenceFinder` per pass) and a `Changer` *or a `via`-lambda* evaluated per non-empty match (1-based `pos`; a non-changer result replaces that match with the error and skips the rest — reference's `enchantScope`; completely empty hooks are skipped). The changer must be enchantable — `Changer.CanEnchant` errors on revision/interaction patches (reference's `notRevisionChanger`). Registers an `Enchantment` on `MacroContext.Enchantments`; `StorySession` runs `EnchantmentPass.Update` over the finished tree after each render and dispatch (the `updateEnchantments()` analogue). The pass is **idempotent**: `Disenchant`s first (unwrapping every `RenderStyleNode` — and string-occurrence `RenderHookNode` — tagged with a `SourceEnchantment`) then re-applies, so any number of runs leaves a single correct application; via-lambda evaluation restores `PendingGoto`/`PendingLoad`, so pass-time macro execution can't clobber a dispatch's queued navigation. `(change:)` is the one-shot sibling: applies immediately against the tree built so far through the shared `EnchantmentPass.Apply`; its wraps carry no source tag and survive across passes.
- **Interactive channel + dispatch.** `IRenderOutput` brackets click/hover regions with `BeginInteractive(InteractiveRegion)`/`EndInteractive()` — symmetric with `PushStyle`/`PopStyle`. Click/hover macros take a `?hookName` *or a string* target (each occurrence wrapped per pass via `TextOccurrenceFinder`, tagged `RenderHookNode.SourceRegionId`; empty string errors, reference's shared `[either(HookSet,String), optional(either(Changer, via-Lambda))]` signature) plus an optional second argument styling the *armed* region — a changer (same `notRevisionChanger` gate as `(enchant:)`) or a `via`-lambda evaluated per non-empty match with 1-based `pos` through the shared `EnchantmentPass.EvaluateViaLambda`. They are **persistent, mirroring enchantments**: each records an `Interaction` on `MacroContext.Interactions` (target query + arm changer/lambda + composed styles + deferred-hook renderer + combo mode + once flag + kind + stable region id) rather than wrapping inline; a plain (non-combo) macro also plants an anonymous *reveal anchor* node at the macro's own position. `InteractionPass.Update` runs after the main render *and* after every dispatch — `StripWraps` removes every interactive/region-tagged wrap, then each interaction is re-resolved against the complete tree, its non-empty matches (reference's `:empty` skip) wrapped in a `RenderInteractiveNode` (arm-changer style layers outside, tagged `SourceRegionId`), and the `ClickHandlers` registry rebuilt. Re-resolving every pass is why a forward-referenced `(click: ?b)` (target declared later) and click-chains across dispatch work. The session keeps the live tree + interactions + handlers between renders; the host reports an event via `StorySession.DispatchEvent(regionId)`, which drops the fired interaction (single-use — except `(click-rerun:)`, `once: false`, which stays armed), renders its deferred hook in place, through `RenderInPlace`, *wrapped in the composed styles* (so `(b)+(click:?a)[x]` reveals a bold `x` — styles land on content, not the armed region, as in reference), then either fills every reveal anchor (plain macros — the attached hook shows at the macro's position; the anchor is found in the live tree by its `RenderHookNode.RevealRegionId` tag; rerun replaces the prior run's content) or into every target, as a revision does (`-replace`/`-append`/`-prepend` combos; string-occurrence targets found by their `SourceRegionId` tag the same way), then re-runs the interaction + enchant passes and re-flushes. No whole-passage re-render; all matches of one call share one region id; a `(goto:)` in a deferred hook navigates after dispatch. The `-goto`/`-undo` *command* variants (`(click-goto:)`, `(click-undo:)`, hover mirrors — no attached hook, used bare in prose) register an `Interaction` directly via `InteractionCommandMacro` (goto: target passage existence-checked at call time; undo: in-prose error on the first turn via `MacroContext.CanUndo`); their dispatch navigates — `Goto(passage)` or `Undo()`+re-render — instead of filling anything (reference's `enchantDesc.goto`/`undo` branches). The `(link:)` family (`LinkMacro`: `link`/`link-replace`, `link-reveal`/`link-append`, `link-repeat`, `link-rerun`) *creates* its own armed label instead of targeting existing content — apply plants a `RenderHookNode.LabelRegionId`-tagged label hook (re-armed by tag each pass via `Interaction.LabelTarget`; also what `?link` matches) plus a reveal anchor, wrapping the label for the `-replace` variants (the fill removes the link) and a sibling otherwise (the link stays); `Interaction.RevealMode` picks how the reveal renders (reveal/repeat append, replace/rerun replace), and a consumed single-use label's tag is cleared so a spent link reverts to plain prose. The optional second changer styles the label; composed changers style only the revealed content, as in reference. `(link-goto:)` returns a command that renders through the same `Visit(LinkNode)` as the `[[...]]` syntax (reference: the link syntax is "a syntactic shorthand for (link-goto:)"); `(link-undo:)` plants a label-only interaction through the same undo dispatch branch, rendering its optional alt text instead when no past turn exists.
- **Printed markup, `{…}`, and nested-render limits.** A string printed into prose (`(print:)`, `$var`, any macro's String result) is tokenized and parsed under the story's profile and rendered in its own temp and conditional scope, as a `(display:)` is; arrays print per item, and other values print literally (a changer through `HarloweValue.OfLiteralText`, which saves as its `(print:)` call). Hook markup with no partner (`[`, `]`, `|name>`, `<name|`) stays literal text, as in reference's front-token demotion, while `[=` is an unclosed hook running to the end of its container. `{…}`/`{=` parse to `CollapsedNode` and count toward the parser's nesting limit; they render as a `RenderHookNode` marked `WhitespaceMode.Collapse`, printed output inside is marked `Preserve`, and `WhitespaceCollapser` runs over the page once the passage has rendered, before the interaction and enchantment passes. After that, each later render (a click's reveal, a revision it runs, a live tick, `(show:)`, and every hook rendered inside one) collapses on its own as it finishes, through `WhitespaceCollapser.CollapseRendered`, and the rest of the page is left as it was, as reference's `Section.execute` collapses each render. A sentinel node marks where reference's first new node ends, since the before and after text it looks for are taken from there. A revision or deferred hook keeps the whitespace rule of where it was written. `MacroContext.EnterNestedRender` bounds `(display:)` and printed markup by depth and a per-render budget of expanded source, which each revision target's rendering also spends, and `MaxRenderNesting` (128) caps open hooks plus nested renders so a recursive story can't overflow the host's stack. `TrySpendOnTargetWalk` limits how much page-searching the targeting macros do per render or dispatch, and refuses them once the page is `MaxTargetedTreeDepth` (512) deep, because each one can add a wrapping layer that every later walk recurses through.
- **Custom macros** (`Runtime/CustomMacroRunner.cs`, `Runtime/Macros/CustomMacroMacros.cs`; reference's `ts/macrolib/custommacros.ts`). A `[` in expression mode opens a **code hook**: a Body frame with its own `MarkupFronts`, so markup inside can't pair with markup outside, parsed by the body parser into `CodeHookNode` and evaluated to a `CodeHookValue`. A hook read back from a save keeps only its source and parses on first use under the *story's* profile, because save values lex under `SaveFormat`. `(macro:)` builds a `CustomMacroValue` from `TypedVarValue` parameters; a name with a `$`/`_` sigil is a call (`MacroNames.IsCustomCall`, checked before `Normalize`, which would turn `(_a:)` into `(a:)`). The runner type-checks, binds the parameters in an isolated temp scope, and renders the body into a throwaway tree, so its prose never shows; any error in it becomes one summary error. `(output-data:)`/`(error:)` return a `CommandValue` that sets the `CustomMacroFrame` when it runs in prose, and `MacroContext.RenderBlocked` then stops the body. `(output:)` is a changer whose `OutputPatch` makes `BodyRenderer.CaptureOutput` keep the hook, changer and visible temps as a custom command instead of rendering; that command renders when it reaches prose. Commands save through the engine-only `(custom-command:)` macro, which only a restoring context can run. Recursion is bounded by `MaxRenderNesting`, the expression-depth limit in the runner, and `EnsureSufficientExecutionStack`. **Typed variables:** `-type` evaluates to a `TypedVarValue`; `WriteVariable` is the one store-write path, applying reference's `canSet`. Story restrictions live on the store and ride the timeline as `Moment.TypeDelta`. A restricted variable can't lose a value to `(move:)` in 3.3.9. **`startup`** passages render ahead of the first turn's passage, sharing its frame. A deferred click/hover/link hook keeps the temp scopes it was armed in (`IVariableStore.CaptureScopeChain`), and each `(for:)` iteration has its own scope so a click finds its iteration's value.
- **Attachment and commands as values** (`BodyRenderer.FollowChanger`, `BuiltinCommands`; reference's `runExpression`). The parser attaches a hook directly after a macro or variable and records the whitespace between as `HookGap`; the rest is decided at render. Only a changer removes that gap. An error replaces the expression and a boolean shows or hides the hook, and both keep the gap; other values print, then the gap and hook. A changer with no hook walks its siblings past whitespace, `<br>` and comments: a `+` and another expression compose (a `+` after a non-changer is prose), a hook or named hook takes it, and a command takes it at the command's own position. An expression that can't attach is spent: it reports in the changer's place and its own hook still renders. `_planned` holds what those later positions do. A named hook hidden by a false condition stays in the tree, empty, so a revision can still fill it. In an expression a built-in command is a `CommandValue` (`[[…]]` is `(link-goto:)`), so `(set: $c to (go-to: "x"))` waits until `$c` reaches prose. `BuiltinCommands` records each one's 3.3.9 role: takes a changer, ignores it (`(go-to:)` runs even under `(if: false)`), refuses it, or is an assignment, which runs when evaluated and can't be stored.
- **Hidden hooks, `(show:)` and `(hide:)`** (`Runtime/Macros/ShowMacros.cs`). `|name)[…]`, `[…](name|` and `|name)[=` set `HookNode.IsHidden`. A hidden hook, or a named one hidden by a false condition, is an empty `RenderHookNode` whose `Hidden` holds how to render it and the temp scopes it was written in. Revisions can still fill it. `(show:)` clears `Hidden` and renders into the node, looking in both the live tree and the one still being built, so a hook written in the same click's content can be shown. A changer written before `(show:)` styles the revealed hook, and a false one stops it. `(hide:)` moves a hook's rendered children into `Hidden.Detached`, and `(show:)` puts them back as they were, ignoring any attached changer, as reference does. Hooks, links and the `RenderRoot` are `IHideable`. One still being built (its `Writer`, the builder writing it from open to close) is hidden when it's finished, whoever ran the `(hide:)`, because reference renders a hook's content before running its macros.
- **Datamap names** (`Runtime/DataName.cs`). A datamap is a `Dictionary<DataName, HarloweValue>`, where a `DataName` is a string or a number, as in reference's JavaScript Maps. A string converts implicitly. `ExpressionEvaluator.CheckDataName` is reference's `isValidDatamapName`: it refuses a string beside the number JavaScript reads it as, and the other way round. A number name can be read but not written or deleted through, at any level of a chain.
- **Transitions** (`Runtime/Macros/TransitionMacros.cs`). The `(transition:)` family sets fields on `HookDescriptor.Transition` through `TransitionPatch`, merged into one `StyleSpec` that `BuildDescriptor` adds as the innermost style layer. It's added only when it names a transition, as reference adds no container for a time on its own, except that around a passage link (`Changer.Apply`'s `aroundLink`) a time alone stays, since it sets the passage transition's length. Making things move is the host's job. Time literals (`2s`, `500ms`) tokenize as number literals, which the parser turns into milliseconds.
- **Datasets** (`Runtime/Datasets.cs`). A `Dataset` is a list of unique values in the order added, which is how it prints. `...` and its save source sort it with `NaturalOrder`. `is` ignores order, the 4.0 fix `COMPATIBILITY.md` applies to every profile, where the 3.3.9 build compares in order.
- **Lambda layer.** `LambdaNode` covers every lambda permutation (`where`/`via`/`making`/`each` + implicit-`it`) via nullable clause fields. `HarloweValueKind.Lambda` + `LambdaValue` wrap the AST as an opaque value (reference equality). `LambdaInvoker` is the shared utility every lambda-consuming macro routes through: binds the parameter + `it` slot + 1-indexed `pos` slot per item via `PushBinding`/`PushItBinding`/`PushPosBinding` (IDisposable scope-restore), evaluates the clause through a fresh `ExpressionEvaluator`, restores on dispose. Lambdas see the caller's store at invocation time — no closure capture.
- **Save / load** (`Runtime/Saving/`; design in `SAVE-LOAD-PLAN.md`). The session runs on a `Moment[]` timeline — completed turns `_past`, the live `_present`, undone `_future` (redo) — not an undo stack: `Goto` pushes present→past and clears future, `Undo`/`Redo` move the present between past/future. Each `Moment` holds its turn's forward `$`-var delta, auto-`(goto:)` redirect `Visits` trail, and sparse RNG `(Seed, SeedIter)`; `visits`/`(history:)`/`turns` are *derived* from the trails. Undo/redo/load restore the store + RNG to the restored turn's *start* and re-render to reproduce it (so relative `(set:)`s aren't double-applied; `MulberryRng` — reference's mulberry32 — makes `(random:)` reproduce). Serialisation is **source-based**, matching reference's `varscope.ts`: `HarloweValue.ToSource()` emits Harlowe source re-lexed + re-evaluated on load (`SaveSerializer`), and a `Changer` carries a `Source` stamped at the evaluator's macro-call/`+`-compose sites. `SaveSerializer.SerialiseTimeline` writes a `SaveBlobVersion`-wrapped JSON moment array (via `JsonWriter`; an empty turn compresses to a bare passage name); `DeserialiseTimeline` is atomic + validating (a vanished passage / corrupt value / newer version → error, nothing half-installed). `ISaveStorage` is the host backend (default `InMemorySaveStorage`; null disables saving), storing blob+filename per IFID-prefixed slot key (`SaveKeys`). `(save-game:)`→Bool, `(load-game:)`→a deferred navigation (stages `MacroContext.PendingLoad`; the session installs + shows the loaded passage after the body render; a re-load from a just-loaded passage errors — the session-held `_loadedGame` loop guard, cleared by any new-turn navigation), `(saved-games:)`→Datamap. **Boundary:** a save reproduces the present turn by re-render, so a dispatch-time (click/hover) `(set:)` made with no navigation isn't recaptured (documented on `StorySession.SaveGame`).
- **Host-facing state** (additive extensions, invisible to story code — no macro or expression reaches them, so Harlowe semantics are untouched). `StorySession.TurnData` is an opaque host string on the present `Moment` (`Moment.TurnData`); living on the moment, it moves with undo/redo, is discarded with a redo branch a `Goto` abandons, and round-trips through save/load, and `GetTimeline()` returns detached `TurnRecord`s (resting passage + data) for past + present. Blobs are stamped with the **lowest version that can represent them** (`SaveBlobVersion.Original` = 1, `TurnData` = 2, `DeletedVariables` = 3, `TypeRestrictions` = 4, `Current` = 4): newer only when a saved turn carries turn data, a variable `(move:)` deleted, or a type restriction, so a session with none writes byte-identical v1 blobs (pinned by a golden test in `TurnDataTests`) that older builds still load. `TryGetVariable`/`GetVariableNames` read the story namespace as deep copies (`HarloweVariableStore.DeepCopyValue`, internal) with no side effects; there is deliberately no host write, because a write from outside the story isn't part of any turn's delta, so undo/redo/load couldn't reproduce it.
- All source lives in `HarloweParser/`; data models are simple public-field classes.

## Code Conventions
- **Namespace:** `Harlowe`
- **Indentation:** 2 spaces
- **Braces:** Allman style (opening brace on its own line)
- **Private fields:** `_camelCase` prefix
- **Public properties:** PascalCase; expression-bodied members where concise
- **Data models:** public fields (not properties) for simple DTOs (`HarlowePassage`, `Branch`)
- **Null handling:** return `null` or `string.Empty` for missing lookups, not exceptions
- **No LINQ** — explicit loops and Dictionary lookups

## Temp variable scoping
Temp variables (`_foo`) are hook-scoped via a stack of dictionaries inside `HarloweVariableStore`. Every `Visit(HookNode)` in `BodyRenderer` pushes a fresh scope; entry dies on hook exit. `Set` walks inner-to-outer and writes to the nearest existing declaration (matches reference's parent-walking `set()` loop in `ts/internaltypes/varref.ts`: "inner hooks can modify outer hooks' values"), so a shadow takes the write; fresh declarations land innermost. Story-scoped `$` vars share a single flat dictionary, unaffected. `(for:)` iterations get a fresh scope per iteration for free (each re-renders its hook through the same `Visit(HookNode)` path).

## Error Policy
In-prose errors, never exceptions — mirrors Harlowe's authoring model: a single bad expression renders an inline error at the spot it happened and the rest of the passage continues. `HarloweValue.Error` propagates through the evaluator (every operator short-circuits) and surfaces via `IRenderOutput.Error(message)`. No `try/catch` on the runtime hot path.

**Parse-error recovery.** Same contract at load time. Tokenizer/parser failures don't abort a load — loaders (HTML, Twee, `AddPassage`) catch `HarloweParseException` and substitute a synthetic `ParseErrorNode` via `HarloweStory.MakeParseErrorAst`, so the rest of the story stays usable and the broken passage renders an in-prose error. The tokenizer itself never throws: lex-time authoring mistakes (`gt`, `=>`, `#ff`) become a `TokenType.Error` token that the expression parser raises on reaching it, so they recover per node like any parse error. The body parser additionally recovers *per node*: a `HarloweParseException` in `ParseNodes` is captured as a `ParseErrorNode`, then `TryAdvanceToResumePoint` advances to the next safe body-mode resync — a newline at the same hook depth, or exactly the macro-close parens the failed node still owes (`TokenCursor.NetMacroDepthSince` counts the net macro-opens its consumed span left unclosed) — so well-formed siblings, including a macro immediately after the broken construct, still parse. `HarloweStory.DecorateParseErrors` recursively prefixes nested ParseErrorNodes with the passage name; `HarloweStory.EnsureWholeStubOriginalSource` stashes the source on a wholly-failed stub so `TweeWriter` can round-trip when `RawBody` is null. `TweeWriter.ResolveBody` distinguishes a wholly-stub AST (`IsWhollyParseError`) — prefers `RawBody` — from partial recovery (normal `IsDirty` path through `MarkupPrinter`).

The current shape rests on five load-bearing architectural pivots; everything else is built atop them and future slices should respect them rather than work around them.

- **Descriptor-patch changer model** (v2.3D, matches reference). A `Changer` is a flat `List<IChangerPatch>` over a `HookDescriptor`. New changer kinds drop in as new patch types + descriptor fields — `Apply` never grows a new top-level branch you can't isolate.
- **Render tree between `BodyRenderer` and `IRenderOutput`** (v3A). An addressable, mutable representation of rendered content, so revision/enchantment macros have something concrete to target. `RenderTreeBuilder` *is* an `IRenderOutput`, which is why `Changer.Apply` retargets onto the tree for free.
- **Semantic event channels on `IRenderOutput`** (v2.2 styles, v3D interactive, `?link`-slice links). `PushStyle`/`PopStyle` and `BeginInteractive`/`EndInteractive` are the bracketing primitives engines map to native UI. The interface is the integration contract and is **frozen at its eight 0.2.0 members**, because adding one breaks every host. A later channel is an optional feature: a capability interface (`ILinkLabelOutput` carries `BeginLink`/`EndLink`), an `OutputFeatures` flag for hosts walking `Entries`, and a lowering to core channels in the one internal `OutputFeatureAdapter`, so a host only receives event kinds it opted into.
- **Hook-scoped variable stack** (divergence audit, matches reference `ts/internaltypes/varscope.ts`). Temp variables in a stack of dictionaries pushed at every `Visit(HookNode)`; `Set` writes to the nearest declaration. Story vars stay a single flat namespace. `(for:)`, lambdas, and nested hooks all rely on this. Save/load serialises only the flat story `$`-namespace (the per-turn delta) — temp vars are transient, rebuilt by the load's re-render, not persisted.
- **`Moment[]` session timeline** (save/load slice, matches reference `ts/state/moment.ts`). `_past`/`_present`/`_future` on `StorySession` replace the undo stack; each turn is a forward `$`-var delta + redirect `Visits` trail + sparse RNG `(Seed, SeedIter)`, with `visits`/`(history:)`/`turns` *derived* from the trails rather than stored. Undo, redo, and load all restore the store + RNG to a turn's *start* and re-render to reproduce it; save/load serialises this timeline source-based. Future work (a full-snapshot fidelity model, `(seed:)`, `(forget-undos:)`, a separate new-turn `(go-to:)` vs intra-turn `(redirect:)`) builds on it.
