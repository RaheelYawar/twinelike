# v2.3 — Lambdas + Lambda-Consuming Macros

Forward-looking implementation plan. Not yet implemented. Once each sub-slice ships, fold its summary into `CLAUDE.md` and delete the corresponding section here.

## Goal

Add lambda support to the parser/evaluator and ship the 9 lambda-consuming macros that don't depend on additional infrastructure (HookName matchers, event/live system, custom `(macro:)`). After v2.3, Harlowe stories doing collection operations or list rendering work end-to-end on this library.

## Scope

**In:**
- `LambdaNode` AST + `LambdaValue` runtime value.
- Parser support for `where` / `via` / `making` / `each` clauses, plus implicit-`it` lambdas.
- Variable-store push/pop for parameter binding without disturbing surrounding temps.
- 9 macros: `(find:)`, `(altered:)`, `(folded:)`, `(all-pass:)`, `(some-pass:)`, `(none-pass:)`, `(rotated-to:)`, `(sorted:)`, `(for:)`.
- `MarkupPrinter` round-trip for every lambda shape.

**Out (deferred to v2.4+):**
- HookName value kind + `(click:)` family + `(change:)` + `(enchant:)` (need named-hook targeting + click event dispatch).
- `(event:)` + `(live:)` + `(trigger:)` (need async/live re-evaluation).
- Custom `(macro:)` + `(output:)` (advanced; defer until lambdas are proven).
- `(unpack:)` destructuring patterns (share parser DNA with lambdas but separate surface).

## Architecture

### `Ast.Expression.LambdaNode`

```csharp
public class LambdaNode : IExpressionNode
{
  // Bound parameter. Null if implicit-`it` form (e.g. `where it > 5`).
  public string ParameterName;
  public bool ParameterIsTemporary;
  public string ParameterType;        // null if untyped (e.g. `_x`); else `"num"`/`"str"`/etc.

  // Accumulator parameter for `making _r ...` (only set for fold lambdas).
  public string MakingName;
  public bool MakingIsTemporary;
  public string MakingType;

  // Clause expressions — null if absent. A given lambda has at most one of
  // {Where, Via}; `making` always pairs with `Via`.
  public IExpressionNode WhereClause;
  public IExpressionNode ViaClause;
  public IExpressionNode WhenClause;  // reserved for v2.4 (event:) — keep null in v2.3

  // True for the `each _x` form (iteration parameter, no body clause).
  public bool IsEach;
}
```

Single node covers all lambda permutations; nullable fields keep variant cost flat. Visitor gets one new `Visit(LambdaNode)`.

### `Runtime.LambdaValue`

```csharp
public class LambdaValue
{
  public LambdaNode Node;
}
```

Lambdas in Harlowe see the caller's scope at invocation time — no closure capture needed. The value is a thin wrapper around the AST. `HarloweValueKind.Lambda` joins the tagged union; `IsTruthy = false`; `ToHarloweString` → empty (lambdas are opaque).

### `Runtime.LambdaInvoker` (new helper)

Single shared utility used by every lambda-consuming macro:

```csharp
public static class LambdaInvoker
{
  // Bind parameter, evaluate where-clause as predicate, restore. Returns Bool.
  public static HarloweValue EvalPredicate(LambdaValue lambda, HarloweValue item, MacroContext ctx);

  // Bind parameter, evaluate via-clause, restore. Returns transformed value.
  public static HarloweValue EvalTransform(LambdaValue lambda, HarloweValue item, MacroContext ctx);

  // Bind both accumulator and item, evaluate via-clause. For (folded:).
  public static HarloweValue EvalFold(LambdaValue lambda, HarloweValue acc, HarloweValue item, MacroContext ctx);

  // Bind parameter, return the bound store-scope token (caller renders body, then disposes).
  // For (for:) where the consumer is BodyRenderer, not an evaluator.
  public static IDisposable BindEach(LambdaValue lambda, HarloweValue item, MacroContext ctx);
}
```

All paths short-circuit on `HarloweValue.Error` and propagate it.

### Variable-store scope push/pop

`HarloweVariableStore` gains a lightweight scope mechanism for lambda parameter binding — strictly isolated from the existing `Snapshot` (which is full-store deep-copy for undo).

```csharp
public IDisposable PushTempBinding(string name, HarloweValue value);
// On dispose: restore prior value of that name in the temp bucket (or remove if absent).
```

Single-name push/pop is enough — lambda invocation only binds 1 (predicate/transform) or 2 (fold/`each` body) names. No need for a full scope stack.

### Parser strategy

`HarloweExpressionParser.ParseExpression` gets a new pre-step `TryParseLambda` that fires in two cases:

1. **Leading parameter:** `[VarRef] (where|via|making)` — consume the variable as the parameter, loop clauses (`where`, then optional `via`, OR `making _r via _r ...`).
2. **Implicit-it:** the next token is a clause word (`where`/`via`) — parse as a lambda with `ParameterName = null`, evaluator binds `it` instead.
3. **`each` form:** leading `each` (UnaryPrefix word op) followed by a `VarRef` — produces a lambda with `IsEach = true` and no clauses.

If `TryParseLambda` doesn't match, fall back to existing precedence-climbing.

Lambdas only appear in macro argument positions (parser sees them inside `(name: ...)`), so `TryParseLambda` can be checked once per argument.

### Implicit `it` in lambda bodies

`(find: where it > 5, $list)` — when `ParameterName` is null, the lambda body uses the implicit `it` slot. The evaluator already maintains an `It` slot on the variable store; lambda invocation writes the bound value there before evaluating the clause, restores afterward. Cheap to support in 2.3A.

### `(for:)` integration with the changer pipeline

`(for:)` returns a Changer (per the manual). Cleanest path: model it as a special `Changer` subtype carrying a lambda + items, so `BodyRenderer`'s existing changer-with-attached-hook intercept can re-render the hook once per binding. Implementation in 2.3D will likely require `Changer` to grow a virtual `Apply` (today it's a flat list of `StyleSpec` layers) — or `(for:)` returns a separate `IBodyRepeater` value kind that the renderer handles directly. Decide in 2.3D, not 2.3A.

## Sub-slices

### 2.3A — Lambda foundation + `(find:)` + `(all-pass:)`

**Lands:**
- `Ast.Expression.LambdaNode` + visitor extension.
- `HarloweValueKind.Lambda` + `LambdaValue` + factory + ToHarloweString/IsTruthy/equality.
- Parser: `TryParseLambda` covering `[var] where ...`, `where it ...`.
- Evaluator: `Visit(LambdaNode)` + scope push/pop on `HarloweVariableStore`.
- `LambdaInvoker.EvalPredicate`.
- `(find:)` macro.
- `(all-pass:)` macro.

**Touches:** parsing/, Ast/Expression/, Runtime/, Runtime/Macros/, all body-AST visitors that recurse into expressions (extend with `Visit(LambdaNode)` no-op or recurse).

**Tests:** parser shape tests (param + clause, implicit-it, no clause = error), evaluator scope-isolation tests, `(find:)` happy path + edge cases (empty input, no matches, error-in-predicate), `(all-pass:)` mirror set.

### 2.3B — `via` + `(altered:)` + `(some-pass:)`/`(none-pass:)`

**Lands:**
- Parser: clause loop accepts `via` after `where`, or as the only clause.
- `LambdaInvoker.EvalTransform`.
- `(altered:)`, `(some-pass:)`, `(none-pass:)` macros.

**Tests:** transform path, predicate variants, mixed `where ... via ...` (rare but legal).

### 2.3C — `making` + `(folded:)` + `(rotated-to:)`

**Lands:**
- Parser: `making _r via ...` two-parameter lambda form.
- `LambdaInvoker.EvalFold`.
- `(folded:)` macro.
- `(rotated-to:)` macro (uses predicate, but listed here because it sits in the data-utility tier).

**Tests:** fold initial/empty/single-item cases, accumulator-shadows-temp test, `(rotated-to:)` various pivot positions.

### 2.3D — `each` + `(for:)` body iteration

**Lands:**
- Parser: `each _x` form → `LambdaNode { IsEach = true }`.
- Decide on `(for:)` integration mechanism (Changer subtype vs. dedicated value kind).
- `(for:)` macro + BodyRenderer wiring.
- `LambdaInvoker.BindEach`.

**Tests:** body iteration over arrays/strings/datasets, attached-hook rendering per binding, `(for:)` over empty input emits nothing, error-in-iterable propagates.

### 2.3E — `(sorted:)` cleanup tier

**Lands:**
- `(sorted:)` with two arities: no-lambda (default ordering — string-aware, number-aware) and lambda (custom comparator — likely a 2-parameter `via` form returning a comparison number).

**Tests:** default sort over numbers/strings, custom comparator, mixed-kind input errors out.

## Cross-cutting concerns

### MarkupPrinter

Each clause needs canonical printing. Round-trip tests live in `MarkupPrinterRoundTripTests`. Canonical form per Harlowe docs:

- `_x where _x > 5`
- `_x via _x * 2`
- `_running making _x via _running + _x`
- `each _x`
- `where it > 5` (implicit-it)

Spaces around clause keywords (consistent with binary-op formatting).

### Error propagation

- Lambda evaluation that produces `HarloweValue.Error` → consuming macro short-circuits and returns the error (it propagates through `IRenderOutput.Error`).
- Mismatched arity (`(find: lambda)` — no items) → in-prose error.
- Lambda used where non-lambda expected, or vice versa → in-prose error in the consuming macro.
- Variable-store rollback on lambda-internal error: `LambdaInvoker.*` methods restore scope in a `finally`.

### Recursion / depth

Lambda invocation alone doesn't recurse. Once `(macro:)` lands (later), we'll need a depth limit. Not a concern for v2.3.

### Visitor extension cost

`IExpressionVisitor` gains one method (`Visit(LambdaNode)`). All implementations get a default no-op or recurse-into-clauses override. `MarkupPrinter` (the only existing IExpressionVisitor that does meaningful work) needs the canonical-form override.

## Open questions to settle before 2.3A

1. **Lambda AST shape** — single `LambdaNode` with nullable clauses (preferred), or chain of clause-specific nodes? Single node is cleaner for downstream consumers.
2. **`LambdaValue` vs. `CustomMacroValue`** — separate kinds when `(macro:)` lands later, or fold to one `Callable`? Lean separate (different invocation semantics).
3. **Implicit `it` shipping in 2.3A** or deferred? Lean ship-now (cheap, common in real stories).
4. **`(for:)` mechanism in 2.3D** — extend `Changer` polymorphism, or dedicated `IBodyRepeater` value kind? Decide when 2.3D starts; not blocking earlier slices.

## Test strategy

- Each sub-slice adds focused unit tests (parser, evaluator, macro behavior).
- One integration test per sub-slice driving an end-to-end Harlowe snippet through `StorySession`.
- `MarkupPrinterRoundTripTests` gains 5–8 lambda-shape round-trips per sub-slice.

## What v2.3 doesn't ship and why

- **No HookName/revision macros** (`(click:*)`, `(change:)`, `(enchant:)`). They take lambdas, but lambda is the smallest piece — they need named-hook targeting and click event dispatch. Their own slice.
- **No event/live system** (`(event:)`, `(live:)`, `(trigger:)`). Async re-evaluation is its own architecture.
- **No custom `(macro:)`**. Explicitly advanced per Harlowe docs; lower-priority for typical stories. Separate slice once lambdas have soaked.
- **No `(unpack:)`**. Destructuring is a different surface; share parser DNA with lambdas but not strictly part of v2.3.
