- **`exits` / `exit` identifier** is unimplemented. Reference Harlowe (see the `exits` getter in `ts/section.ts`) reports the number of clickable interactive elements currently on screen — used in patterns like `(if: exits is 0)[Game over]`. Implementing it cleanly requires a live re-evaluation model: the count changes mid-render as interactive elements are added, and reference's eval engine re-runs expressions after each add. Our impl doesn't have live re-evaluation; adding it is a substantial slice that's adjacent to the `(live:)` / `(event:)` work in the candidate-next-slices list. `turns` / `turn` was the easy half and shipped; `exits` defers until the live system lands.
- **Elided comparison `is < 5`** is unimplemented. Reference Harlowe lets authors chain comparisons against an implicit operand carried through `and`/`or` chains — `(if: $a is 5 and is < 10)` means "$a is 5 and $a < 10". Reference's runner.ts (`getElisionOperands` plus the `isComparisonOp` walker) detects when an `and`/`or` sibling is a comparison and propagates its LHS across the chain, including ambiguity-error handling for `is not` chains. A parser-only rewrite to `it < 5` looks tempting but produces silently wrong results — our `it` slot updates only on `Set`, not after each comparison, so the elided form would compare against stale state. Proper implementation needs evaluator changes to track comparison LHS across `and`/`or` operands. Defer until the rest of the comparison/logic plumbing settles.
- **`--` comment family** is unimplemented. Reference Harlowe defines four related comment forms (documented in the `comment` rule of `ts/markup/patterns.ts`): (1) token-skip inside macro args — `(set: $x to --2 6)` deletes the `--` and the next token; (2) line comments — `-- prose` at line start drops prose up to the next non-prose boundary; (3) comment hooks `--[...]` — block comments, nestable, the most useful in real authoring; (4) HTML comments `<!-- ... -->` — likely already pass through because we forward HTML tags raw. The four layers touch different parts of the pipeline (tokenizer + expression parser for #1, body parser for #2 and #3) so each adds real surface. The practical subset is #1 + #3; the full feature is all four. Defer as a single "Comments" slice — implementing only one form would be a partial feature that authors find confusing.
- `(background:)` image-vs-colour heuristic is **inverted** from reference Harlowe (see the `["background", "bg"]` entry in `ts/macrolib/stylechangers.ts`). Reference rule: "colour only if hex / function-call shape; else image (default to `url(value)`)." Ours: "image only if URL prefix / image extension; else colour." Diverges on named CSS colours (`"blue"`, `"navy"`) — we treat as colour, reference treats as image URL — and on extensionless paths. Reference's design presumes authors pass a typed `Colour` value (from `(rgb:)`/`(hsl:)`/`(lch:)`) for named colours; we don't have a typed `Colour` runtime value yet so we picked the more author-intuitive default. Re-aligning would require landing a typed `Colour` first.
- **Unified recursion ceiling.** Reference Harlowe uses a single 50-frame stack cap covering hook nesting, `(display:)`, `(for:)` iteration, lambda evaluation, AND consecutive `(goto:)`s — see the `this.stack.length >= 50` check in `ts/section.ts`. Ours uses separate per-axis caps: `MaxGotoDepth=20`, `MaxDisplayDepth=20`/`AbsoluteMaxDisplayDepth=256`. Different stories hit limits in different impls. Our per-axis model is arguably more debuggable (the error message tells the author which axis ran away), but error reporting diverges and a story tuned against reference's unified cap could behave differently here. Migration would mean retiring the per-axis counters in favour of a single `MacroContext.StackDepth` incremented at every recursion point.
- **`TwineError` type discrimination.** Reference's `TwineError` (see `ts/internaltypes/twineerror.ts`) carries a typed kind — `syntax`, `operation`, `macrocall`, `datatype`, `custommacro`, `infinite`, `property`, `unimplemented`, `propagated`, `user`, `assertion`, `debugonly` — each with a distinct default explanation. `(assert:)`, debug mode, and error propagation all branch on the type. Our `HarloweValue.Error` carries just a string; two errors with identical messages but different conceptual kinds are indistinguishable. Add a kind enum (or string tag) when a feature surfaces the need — debug mode and `(assert:)` are the natural triggers.
- **`(history:)` returns undo-stack order, not Moment-timeline order.** Reference Harlowe's `(history:)` walks the `Moment[]` timeline (`ts/state.ts`). Ours iterates the undo stack via `_undoStack.ToArray()` — same answer for single-redirect navigations, but a passage that fires multiple `(goto:)`s in one turn collapses to a single undo entry in ours and to multiple Moments in reference. Resolves once the save-model slice lands a real Moment timeline.
- ✅ **FIXED (2026-06-01) — Non-ASCII Unicode digits crashed the loader (real bug, not a divergence).** The tokenizer's number-literal dispatch gated on `char.IsDigit`, which returns true for non-ASCII decimal digits — Arabic-Indic (U+0660–0669), fullwidth (U+FF10–FF19), Devanagari, etc. So a body like `(print: ٥)` or `(set: $x to ５)` emitted a `NumberLiteral` token carrying the non-ASCII digit string, and `ParseAtom`'s `double.Parse(t.Value, CultureInfo.InvariantCulture)` threw `FormatException`; the loaders catch only `HarloweParseException`, so it escaped and aborted the entire load — a direct violation of the "in-prose errors, never exceptions" policy. **Fix:** restricted the tokenizer's number/ordinal digit gates to ASCII `'0'..'9'` via a new `HarloweTokenizer.IsAsciiDigit` helper, so non-ASCII digits fall through to identifier/text handling (matching reference's ASCII-only `\d` in `ts/markup/patterns.ts`). See `IsAsciiDigit` and the `NonAsciiDigit_*` tests in `HarloweTokenizerTests`/`StorySessionTests`. (Defence-in-depth alternative not taken: switching `ParseAtom` to `double.TryParse` + `ParseErrorNode`. Could still add later as belt-and-suspenders.)
- **`(click:)`/`(replace:)` families silently no-op on `?link` targets (real bug).** `HookResolver.Resolve` matches `?link` to `RenderLinkNode`s, but `RenderLinkNode` doesn't implement `IRenderContainer`, so `Changer`'s interaction wrap loop and `Splice` both skip every match (`if (!(targets[i] is IRenderContainer container)) continue;`, and the same guard in `Splice`). `(click: ?link)[…]` registers no handler and never fires; `(replace:/append:/prepend: ?link)` does nothing — all with no diagnostic, even though the resolver documents `?link` as a supported target. Fix: either make `RenderLinkNode` a container (give it children carrying its text) or special-case link wrapping in the interaction/revision paths. Distinct from the string-target click/hover candidate slice (that's `(click: "literal")`); this is the hook-name `?link` selector.
- ✅ **FIXED (2026-06-15) — Interaction macros now re-resolve `?target` as a persistent pass, mirroring `EnchantmentPass`.** `Changer.RunInteraction` records an `Interaction` (target query + cloned styles + deferred-hook renderer + mode + kind + stable region id) on `MacroContext.Interactions`; `InteractionPass.Update(root, interactions, clickHandlers)` (`Interaction.cs`) runs after the body render *and* after every dispatch — `StripWraps` removes all interactive/region-tagged wraps, then each interaction is re-resolved against the complete tree, re-wrapped, and its handler re-registered. `DispatchEvent` drops the fired interaction and re-runs both passes (the targeted `UnwrapInteractive` is gone; `StripWraps` is its id-agnostic generalization). Forward refs (`(click: ?b)[…] |b>[…]`) and click-chains across dispatch now work; covered by `Click_TargetDeclaredLater_*`, `MouseOver_TargetDeclaredLater_*`, `Dispatch_ClickChain_*`, `Dispatch_OneRegion_LeavesOtherSingleWrapped` in `InteractionMacroTests`. Reference Harlowe models clicks as **enchantments** that re-resolve whenever the DOM changes, which is why forward references and chains work there. **Fix (mirror `EnchantmentPass`):** add a persistent `MacroContext.Interactions` list (target query + deferred-hook renderer `Action<IRenderOutput>` + mode + kind + composed style layers); `RunInteraction` records onto it instead of wrapping inline; a new idempotent `InteractionPass.Update(root, interactions, clickHandlers)` runs after the body render *and* after each dispatch — first unwrapping every `RenderInteractiveNode`/region-tagged `RenderStyleNode` (the `UnwrapInteractive` sweep generalized), then re-resolving each interaction's target against the now-complete tree, re-wrapping, and re-registering handlers under stable region ids. Must keep single-use semantics (a consumed/dispatched interaction stops re-wrapping) and interleave correctly with the enchant pass and revision splices. Substantial slice with real regression risk to the working dispatch path — do as its own focused change with a dedicated test pass (forward-ref click, click-chain across dispatch, hover mirrors, composed-style interaction, idempotency under repeated passes). Related to the `?link` no-op above and the string-target click slice in the candidate list.
- ✅ **FIXED (2026-06-18) — Passage names weren't escaped on Twee write nor unescaped on read (real bug, round-trip data loss).** `TweeWriter.AppendHeader` emitted `passage.Name` raw and `TweeReader.ParseHeader` stopped the name at the first raw `[`/`{`, so `Choose [A]` round-tripped to name `Choose` + bogus tag `[A]`. **Fix (symmetric, mirroring the existing tag-escape pair):** a new `AppendEscapedName` escapes `\ [ ] { }` on write (allowing whitespace — names may contain spaces, unlike tags); `ParseHeader`'s name scan now skips `\X` pairs and stops at the first *unescaped* `[`/`{`, then a new `UnescapeName` strips the backslashes (tolerant `\q`→`q`). Verified against the IFTF Twee 3 spec (*"names that include … `[`, `]`, `{`, `}` must escape them … non-escape backslashes must also be escaped"*). See the `PassageName_*` tests in `TweeReaderTests` and `PassageName_WithBrackets_EscapedOnWrite`/`PassageName_Escaped_RoundTripsStable` in `TweeWriterTests`.
- ✅ **FIXED (2026-06-18) — `RenamePassage` left inbound `[[…]]` links dangling (real bug).** It re-keyed the lookup but never updated other passages' links, so links targeting the old name resolved to null at render time with no diagnostic. **Research correction:** the original "rewrite `Branch.Name`" suggestion was a no-op — `Branch` is a derived view; the renderer navigates via the AST `LinkNode.Target` (`BodyRenderer.Visit(LinkNode)`), so the real fix had to touch passage source. **Fix (mirrors the Twine editor's `update-passage.ts`):** `RewriteInboundLinks` retargets the three Harlowe link forms (`[[old]]`, `[[disp->old]]`, `[[old<-disp]]`) in every passage's `RawBody` via regex, then reparses (shared `ParseBodyToAst`) to regenerate `Ast` + `Branches`, leaving the passage clean (no `MarkupPrinter` re-canonicalization) so surrounding formatting is preserved. New optional `RenamePassage(old, new, updateInboundLinks = true)` param mirrors Twine's `dontUpdateOthers`. **Documented limitation (as in Twine):** macro string targets — `(goto: "old")`, `(display:)`, `(link-goto:)` — are not rewritten (a string literal can't be told apart from a passage reference); names containing `[`/`]` aren't handled either. See `RenamePassage_RewritesInboundLinks_AllThreeForms`, `_RewritesSelfLink`, `_RegeneratesAstAndBranches`, `_PreservesSurroundingFormatting_PassageStaysClean`, `_UpdateInboundLinksFalse_LeavesLinksAlone`, and `_DoesNotRewriteMacroStringTargets` in `HarloweEditingTests`.
- **Body-parser error recovery can swallow a well-formed sibling macro (real bug).** `TryAdvanceToResumePoint` resyncs on the first depth-0 `MacroClose` with no notion of which macro owns it. When an error is thrown *after* `ParseArgumentList` already consumed the failing macro's own `)` — e.g. the chain-position assignment-macro check in `ParseMacro` that rejects `(set:)`/`(put:)` as changer-chain components — the resync scans forward and consumes the *next* macro's `)`, folding that valid sibling into the `ParseErrorNode`. Trigger: `(set: $x to 5) + (print: 1) tail` loses `(print: 1)`, leaving only ` tail`. Same root cause as the documented nested-malformed-macro edge above; the real fix is threading macro-call depth through the body parser so the catch knows how many `MacroClose` tokens the broken construct owns.
- ✅ **FIXED (2026-06-18) — Hand-rolled `JsonReader` had no recursion-depth cap (real bug, uncatchable crash).** `ReadValue` → `ReadObject`/`ReadArray` → `ReadValue` recursed without limit, so a deeply nested `:: StoryData` body (e.g. thousands of `[`) threw an uncatchable `StackOverflowException` and killed the host — `TweeReader.Read` catches only `HarloweParseException`. Adversarial input only, but it bypassed the in-prose error policy. **Fix:** a `_depth`/`MaxDepth = 128` ceiling in `ReadValue` (the universal recursion choke point — both `ReadObject` and `ReadArray` recurse back through it), incremented before a `try`/decremented in `finally` so it stays balanced as the throw unwinds; past the cap it throws a normal `HarloweParseException`, which `TweeReader` already discards as malformed StoryData. Mirrors the identical caps in `HarloweExpressionParser`/`HarloweBodyParser`. See the `DeeplyNestedJson_*` / `ModeratelyNestedJson_*` tests in `JsonReaderTests` and `StoryData_DeeplyNestedJson_DoesNotCrash_SiblingsSurvive` in `TweeReaderTests`.
- **`Set` aliases collections by reference — no clone-on-set (latent bug).** `HarloweVariableStore.Set` stores the `HarloweValue` reference directly, so `(set: $b to $a)` makes `$a` and `$b` share one backing `List`/`Dictionary`. No shipped macro mutates a stored collection in place, so it's invisible today, but it will bite the moment property-assignment (`(set: $a's 1st to …)`), `(move:)`, etc. land. Reference clones on set when the value already has a knownName (`ts/internaltypes/varref.ts`'s `set()`). Fix alongside (or before) the property-assignment slice: deep-copy Array/Datamap values on `Set`.
- **Twee header position metadata is delimited by the first `}` (real bug, edge).** `ParseHeader` uses `line.IndexOf('}', p)`, so JSON metadata containing `}` inside a nested object or a string value is truncated and the leftover `}` leaks into further header parsing. Position is stored opaque and re-emitted verbatim, so the corruption round-trips out. Twine's flat `{"position":…,"size":…}` avoids it; custom/nested metadata triggers it. Fix: brace-match (respecting strings) instead of first-`}`, or parse the block with `JsonReader`.
- **No pid-uniqueness check in `AddPassage` or the HTML loader (real bug, edge).** Only passage *name* uniqueness is enforced (via `Dictionary.Add`); two passages can share a pid (a hand-edited HTML export with duplicate `pid=`, or an explicit `Pid` colliding with a synthesized one — `NextAvailablePid` only avoids collisions with *existing numeric* pids). `GetPassageByPid` / `GetStartPassage` then returns whichever enumerates first from the unordered dictionary, so resolution is non-deterministic across runtimes on a story that loaded without error. Fix: validate pid uniqueness on `AddPassage`/`Parse` (error, or re-synthesize on collision).
- **A `(goto:)` loop hitting the depth ceiling leaves session state polluted (real bug, edge).** Each hop calls `EnterPassage` (which bumps `_visitCounts` and advances `_currentPassage`) *before* the recursive `RenderInternal`; the `depth >= MaxGotoDepth` check fires only at the top of the next frame. So on abort `CurrentPassage` is some intermediate passage, every cycle passage's `(visits)` is inflated, and no undo snapshot was taken for the intra-render hops — the host gets the "too many redirects" error but the session is left inconsistent. Adjacent to the unified-recursion-ceiling TODO above; fix by checking depth *before* `EnterPassage` and/or restoring `_currentPassage`/visit counts on abort.
- **A non-string `start` in StoryData is silently dropped (real bug, edge).** `ApplyStoryData` reads `start` via `AsString` (`v as string ?? fallback`), so `{"start":123}` (number/bool/null) yields null, `pendingStartName` stays null, and `StartNode` is never set — the story silently loses its start passage rather than coercing or erroring. Fix: coerce non-string scalars, or surface a diagnostic when `start` is present but unusable.

## Candidate next slices

No active slice; this is a candidate list, not a queue. Weigh each against the game-engine audience before defaulting to order.

- **Event/live system** — `(event:)`, `(live:)`, `(trigger:)`. Needs async/live re-evaluation, plus a tick callback channel from the engine to the session.
- **More styling changers (second wave)** — `(border:)`/`(border-colour:)`/`(border-size:)`/`(corner-radius:)`/`(rotate:)`/`(text-indent:)`/`(text-rotate-x/y/z:)`. Follow the same `StylePatch` pattern as v3.1; borders take CSS-shorthand sided args (1=all, 4=t/r/b/l).
- **`(hover-style:)` and `(line-style:)`/`(char-style:)`/`(link-style:)`** — need a pseudo-state field on the descriptor and per-line/char/link tree iteration respectively. Their own slice.
- **String-target click/hover** — `(click: "some text")[…]`, analogous to string-target revision. Reuses `TextOccurrenceFinder`; deferred from v3D to keep scope tight.
- **`(link:)` family** — `(link-replace:)`, `(link-reveal:)`, `(link-goto:)`. Interaction macros that *create* new link elements rather than wrapping existing hooks. Reuses v3D's interactive channel.
- **Story-wide `(enchant:)`** via `header`/`footer`-tagged passages. Needs cross-passage enchantment threading on `StorySession`.
- **Transitions** — `(t8n:)`, `(transition:)`, `t8n-depart`/`t8n-arrive`. Slot in as another `IChangerPatch` per the v2.3D model; engine consumers need a transition descriptor channel.
- **Custom `(macro:)` + `(output:)`** — author-defined macros. Explicitly advanced per Harlowe docs; lower priority for typical stories.
- **Convenience syntax** — property assignment (`(set: $person's name to "Bob")`), `(unpack:)` destructuring, `...` spread, storylets, dataset evaluation. Authors can work around all with longer forms; quality-of-life rather than capability.
- **Save/load model** — `Moment[]` timeline replacing the current undo-stack snapshot model, plus `(save-game:)` / `(load-game:)` / `(saved-games:)` / `(delete-save:)` macros, plus a seedable PRNG so `(random:)` and `(either:)` results are reproducible across save/load. Reference's `ts/state.ts` is the model — serialise/deserialise to a JSON-ish blob, host-supplied storage backend (so Unity/Godot consumers plug their own save system; web consumers use `localStorage`). Also unlocks correct `(history:)` semantics, `(redo:)`, and `(mock-visits:)`/`(mock-turns:)`. The largest single slice in this list but with the highest author-visible payoff per line — four headline macros land at once. ~500 lines + tests, roughly 1–2 days of focused work. **Detailed plan + open design questions in `SAVE-LOAD-PLAN.md` at the repo root** — read that before starting; six prerequisite decisions block step 1.
- **Missing value types.** Reference Harlowe has typed values for `Colour`, `Gradient`, `Dataset`, `Datatype`, `TypedVar`, `VarBind`, `Command`, `CustomCommand`, `CodeHook`, `Pattern`, `ImageAsset`, `Measure` — each defined in `ts/datatypes/`. We have `Number`, `String`, `Bool`, `Array`, `Datamap`, `Error`, `Changer`, `Lambda`, `HookName`. Each missing type unlocks a macro family: `Colour` enables `(rgb:)`/`(hsl:)`/`(lch:)`/colour math/the `(background:)` re-alignment; `Dataset` enables `(ds:)` literals + set operators; `Datatype`/`Pattern` enable runtime type checks and `(if: $x is a Number)` (lexer half is already done — `HarloweTokenizer` fuses `is a`/`is not a` into operator tokens; the slice just needs `ExpressionEvaluator`'s binary-op switch, which today handles `is`/`is in`/`is not in` but has no `is a`/`is not a` case, to grow those arms); `TypedVar` + `VarBind` enable typed temp vars and `2bind`; `(macro:)` + `Command` + `CodeHook` enable author-defined macros. Land independently as separate slices — start with `Colour` since `(background:)` already has it as a tracked TODO above.
- **HookSet vocabulary** — extend `HookNameValue` / `HookResolver` beyond ordinal narrowing to support `?passage's chars` (per-character wrapping for animations), `?passage's lines` (per-line styling), `?passage's links` (link-only selectors), ranged narrowing (`1stTo3rdlast`), array-of-indices selectors (`?red's (a:1,2,4)`), and HookSet composition via `+` (`?red + ?blue` is a single selector matching both). Reference impl in `ts/datatypes/hookset.ts`. Medium-sized slice; enables documented authoring idioms like character-by-character text reveals and line-striping.
